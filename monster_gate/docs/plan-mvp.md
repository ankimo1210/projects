# MVP 実装計画 — Web / MP 方式 / 1 ダンジョン

決定事項（2026-08-29）: プラットフォーム Web、コストは GBA 式の MP、対戦なし、まず 1 ダンジョン。
元ネタの調査は `research-original-game.md`。

## 1. MVP のスコープ

**入っているもの**
- 職業 1 つ（戦士）。ステータスは 攻撃 / 防御 / HP / MP。
- 1 ダンジョン「ゆかい」相当: 7F、部屋グリッド生成、敵 6〜7 種、最下層に祭壇（クリアの証）。
- カード: 持ち込み 10 枚、ダンジョン内で拾える。MP を消費して発動。
  最初の 12 種: ポーション 20/40/80、ファイア、マルチファイア、サンダー、スリープ、
  ヘイスト、ブライト、ワープ、エスケープ、ブロンズソード。
- MP: 新しい部屋に入ると回復、カードを捨てると消費 MP 相当を回収（GBA 準拠）。
- 成長: 敵撃破で 攻/防/HP 上昇、敵種ごとの上限あり。新部屋で HP+5。
- 敵 AI: 部屋内で待機 → 視認で最短経路接近、見失ったら最終位置へ、飛び道具は直線上で射撃。
- 結果: クリア = WIN 獲得、死亡 = WIN 半額。WIN はカードを買う通貨（拠点画面は最小限）。
- 倉庫（100 枚）と持ち込み選択画面。localStorage に保存。

**入っていないもの**（後続フェーズ）
- 他職業、ダブルアップ、ショップ/カジノ、装備の多様化、ボス、特殊ルール城、対戦/城占領、サウンド。

## 2. 技術スタック

- TypeScript + Vite、描画は Canvas 2D（フレームワークなし）。UI は最小限の DOM。
- テスト: vitest（エンジンは純粋関数なので大半をユニットテストで検証）。
- pnpm@11.1.0（`npx --yes pnpm@11.1.0 …`。ワークスペースの ts-rosetta / b737-ops-sim と同じ）。Node 22。
- タイル絵はまず色付き矩形 + 文字。アセットは後回し。

## 3. アーキテクチャ

```
monster_gate/
  src/engine/        # 純粋・決定的。DOM/Canvas を知らない
    rng.ts           # seeded PRNG（テスト再現性）
    types.ts         # Tile, Entity, Card, DungeonState, Action, Event
    mapgen.ts        # 部屋グリッド + 通路
    fov.ts           # 部屋 5 マス / 通路 1 マス（ブライトで全画面）
    ai.ts            # 敵の行動決定
    combat.ts        # ダメージ計算、成長
    cards.ts         # カード定義（データ）と効果関数
    turn.ts          # step(state, action) -> { state, events }
    dungeon-def.ts   # 「ゆかい」の階層/敵/カード出現テーブル
  src/game/          # 進行・保存
    meta.ts          # 倉庫、WIN、持ち込み選択、localStorage
  src/ui/            # Canvas 描画、入力、画面遷移
  tests/             # vitest
```

- `step(state, action)` が唯一の状態遷移。イベント配列（攻撃した、拾った、階段…）を返し UI が演出に使う。
- 数値テーブル（BET/WIN、敵 HP、成長上限、MP 回復量）はすべて `dungeon-def.ts` / `cards.ts` のデータに寄せ、調整可能にする。

## 4. フェーズと検証基準

| # | 内容 | 完了条件 |
|---|---|---|
| 0 | scaffold（Vite/TS/vitest/eslint）、README | `pnpm test` `pnpm typecheck` が通る |
| 1 | mapgen + fov | 1000 seed で全部屋が連結、階段到達可能（テスト） |
| 2 | turn/移動/攻撃/成長、敵 AI | 敵が接近・攻撃する、上限で成長停止（テスト） |
| 3 | カード + MP | 12 種の効果テスト、MP 回収の等式が成り立つ |
| 4 | Canvas UI で 1 フロアを遊べる | 手動プレイで 7F 到達〜クリア/死亡まで通る |
| 5 | 拠点: 倉庫・持ち込み・WIN・保存 | リロード後も倉庫が残る |
| 6 | バランス調整 | 戦士・初期カード（ポーション×3, ファイア×3）でクリア率をシミュレータで計測 |

フェーズ 6 の結果（2026-08-29, 200 seed）: 初期手札（ポーション×4, ファイア×3）で **クリア 21%**、空手札で 10.5%、
死亡は 4F〜7F に分散（7F ドラゴンが最多）。ボットは戦術なしの素直な探索なので、人間の初見 3 割前後に相当すると見て採用。
per-kill 成長は ATK が伸びすぎて調整不能だったため、隠しレベル（XP）方式に変更した（`spec-mvp.md` §5）。

## 4.7 見た目の作り直し（2026-08-29）

アーケード版・GBA 版の画面に寄せて HUD を組み直したあと、上から見下ろす記号表示
（ドット絵風）は「楽しくない」という指摘を受け、**クォータービュー（2:1 の等角投影）**へ全面差し替え。

- 壁は高さのある箱（天面 + 左右側面）、床は厚み 6px の板、キャラは足元に楕円の影
- カメラはプレイヤーへ補間追従、移動も 130ms で補間（`requestAnimationFrame`）
- キャラ/アイテム/施設は絵文字のビルボード（画像アセットなしで色と形が付く）
- 手前の壁に隠れたときはプレイヤーのゴーストを 50% で重ねる（壁を透過させると穴に見える）
- 詳細は `docs/spec-mvp.md` §10

## 5. 最初に決めた仮定

- 1 ターン = プレイヤー 1 行動 → 全敵 1 行動。ヘイストはプレイヤー 2 行動。
- ダメージ = max(1, 攻撃 − 防御) ± 小さな乱数。魔法は防御無視、射程は直線。
- MP 上限 100、初期 30、新部屋で +10。
- 敵の「見失い」は最終確認位置に到達したら部屋ランダム巡回。
