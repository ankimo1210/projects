## 4. 次の候補の推奨（2026-10-21 に見直し。ユーザーが決める）

**推奨：15（DP-DPO）を方法の研究として先に小さく行い、次に 25（Kronos）。10（EXFormer）は保留する。**

旧版の推奨は「10 を、17 と 26 を物差しにして、日次の為替予測の反証として設計する」でした。Codex が一次資料を見直して 15 を先にと提案し、Claude が独立にレビューして同意しました。どちらも、研究の段は何も回していません。

- **10 を保留する理由：** 再実装が成功しても失敗しても、原論文について言えることがほとんど無い。
  - 費用後の成績（表9、取引のたびに 5bp＋スリッページ 2bp）は Sharpe 0.918・1.507・1.003。§5.2 が費用後の Sharpe とする 1.419・2.017・1.876 は Sortino の列。
  - 売買の成績に有意性の検定が無い（Clark–West などの検定は予測の精度だけ）。約1年では年率 Sharpe の標準誤差がおよそ 1.2〜1.5 で、0 と区別できない（Claude の概算）。
  - 窓の長さ T は、テスト期間の成績で選んだ疑いがある。費用前の Sharpe は T=15 だけが 1.89〜2.09 で、ほかの窓（5・10・20・30）は 0.20〜0.94（表5〜8）。本文は15日の窓が最も頑健で収益性が高かったと書くだけで、検証期間で選んだという記述は見当たらない。
  - 表9の比較相手の多くは一定のポジションに潰れている。例：EUR/USD の Informer・Transformer・MLP・LSTM-ARIMA は全指標が同じ値。
  - データは Wind で、コードは非公開。RW の売買は sign(r[t−1]) で、予測側の RW の式は書かれていない。
  - 外生変数は前方補完で、公表日・改定の扱いと、為替と外生変数の終値の時刻のそろえ方が書かれていない。公表日の先読みも、同じ日付の中の先読みも確かめられない。
  - 17 と 26 は EXFormer を否定する根拠にならない（17 は月次、26 は AR 過程と線形の自己注意）。使うなら、比較相手の作り方（切片付きのモデル、同じ入力の線形 AR）の参考にする。
  - 為替を扱うなら、EXFormer の追試ではなく、無料で時刻のそろったデータで「外生変数が翌日の為替を当てるか」を問う一般的な反証に組み替える。ランダムウォークに勝つのは難しいという事前の見込みが強いので（17 も同じ結論）、学べることは小さいと見ている。
- **15 を先にする理由：**
  - 合成データの生成法則が書かれていて、真の最適方策が分かるので、決着がつく。状態 s_t = ±1（直近に上がったか）のもとで、次期の上昇確率は σ(0.1 + 0.8s_t − 0.4s_{t−1} + γ s_t s_{t−1})（γ ∈ {0, 1.2}）、グロスリターンは exp(0.002 + 0.03 s_{t+1})。予測器は σ(θ0 + θ1 s_t + θ2 s_{t−1}) なので、γ=1.2 の交互作用は候補に入らない。
  - データが軽い。
  - 「当たる予測と儲かる予測の違い」（費用込みの判断）は、研究全体の芯に当たる。候補12も片道 2bp の費用で判定が割れた。
  - 作った道具（費用込みの DP、リグレットの評価）を、あとの候補にも使える。
- **15 で期待しないこと（売買シグナル）：**
  - 原論文の実データ（表2、12か月・5bp）では、どの方針も買い持ちに届かない。同じ Stocks.csv で評価期間 2000-01〜2022-05（269か月）の買い持ちを計算すると、S&P 500 が年 4.72%、Nasdaq が年 4.97%（配当なし、Claude の計算、成長率の定義は論文と同じ）。表2の最良は 4.54% と 4.77% で、表2に買い持ちの行は無い。
  - 真のモデルを予測器の候補に含む場合（γ=0）、DP-DPO のリグレットは尤度による方法を 0.00035 上回る（標準誤差 0.00018）。効くのは含まない場合（γ=1.2）で、平滑化なしの DP に比べてリグレットを約73%減らす（差 0.00615、標準誤差 0.00030）。理論どおり。
  - 「学習履歴に依存」は、学習に使う価格の履歴の長さのこと。直近120か月で学習すると18条件中13条件、全履歴だと18条件中5条件で、DP-DPO が尤度に勝った。
- **25 の位置：** 公開済みの強い主張の反証を先にしたいなら、25 が先でもよい。重みが公開されていて、条件は 10 よりそろえやすい。最初に事前学習データの締め日を本文で確かめ、締め日より後のデータが何か月あるかを数える。timesfm_lab の続きなので、新しく学べることは 15 より少ないと見ている。
- **2 DeePM：** ユーザーが先物データの購入を決めた場合だけ。

**15 を選んだら、設計で先に決めること：**

1. 問いを2つに分け、判定のラベルも別々にする。M の勝ちを S の証拠として書かない、と PREREG に書く。
   - M（方法）：情報・予測器の型・費用込みの DP の方策の作り方・費用・目的（E[log W_T]）・調整の予算・乱数の種をそろえたとき、報酬で学習するとリグレットが減るか。
   - S（シグナル）：実データで、どの方針でも、買い持ち・現金・無条件平均の方針を費用込みで上回るか。
2. G0：論文の表1（N=2048、T=12、c=0.01、γ=0 と 1.2、系列64本）を、標準誤差の範囲で再現する。
3. 世界を3つ用意し、予想の向きを先に書く。
   - 真のモデルを含む世界（γ=0）：尤度が DP-DPO 以上。
   - 含まない世界（γ=1.2）：DP-DPO が勝つ。
   - 予測力の無い世界：どちらも無条件の最適方策と同じになる。差が出たら過学習。
4. 固定するもの：入力とそれが分かる時点、予測器の型と係数の範囲、初期値（尤度の解から始める）、τ と更新上限の候補とその選び方、乱数の種と本数、学習に使う履歴の長さ。履歴の長さは先に決めるか検証期間で選び、評価期間の成績では選ばない。
5. 費用の効き目を切り分ける比較相手を足す：尤度の予測器＋費用込みの DP、尤度の予測器＋売買しない幅（幅は検証期間で選ぶ）。DP-DPO の勝ちが「売買を減らしただけ」なら、売買しない幅の方針と同じ成績になる。売買の回数も報告し、費用は 0・現実的・高いの3段階で比べる。
6. 予測の質（負の対数尤度）と判断の質（リグレット、成長率）を並べて報告する。論文でも、表1の条件で、真の分布で評価した負の対数尤度が 0.585 から 0.835 に増えたのに、リグレットは減っていた。
7. 実データには配当と現金の金利を入れる（例：Kenneth French の月次の市場リターンと RF）。論文のように配当なし・金利ゼロにすると、買い持ちと現金の比較が歪む。
8. 検定と多重性：M は系列ごとの対の差で検定する。S は買い持ちとの差をブロック・ブートストラップで検定し、条件の数で Holm の補正をかける。「18条件中13勝」のような勝ち数は判定に使わない。
9. 検出力：月次で約300か月の評価期間で、合成実験で見た大きさの差を検出できるかを先に調べる。できないなら、実データの部分は記述にとどめると先に決める。

## 6. 守ること

- リポジトリは PUBLIC です。秘密情報、ユーザーのメールアドレス（外部 API の User-Agent などにも入れない）、勤務先・顧客の機密は書かない。
- **共有 .venv の同期は、リポジトリのルートで `uv sync --all-packages`（`make sync`）だけ。** 素の `uv sync` はメンバーの依存（pandas など）を全部外す（2026-10-20 に一度起き、すぐ戻した）。どちらでも、ロックの外にある maturin 製の `gto_py`・`gto_cuda` は消える。
- worktree の中では `uv sync`・`uv run` を使わず、共有 .venv の Python に `PYTHONPATH` を付けて動かす。`make test` は単一スレッドの BLAS で動く（Makefile が設定している）。
- 終わった研究の段は回し直さない。
  - 本番 B の lock を外さない。
  - `snapshot` を取り直さない（yfinance は過去の値も変わる）。
  - sector_leadlag_lab の `corrections` は回し直さない。`meta.ran_at` でハッシュが変わり、PREREG §5.3 と結果の `corrections_sha256` が合わなくなる。
- 大きな計算は先に容量を見積もる。1つの出力先が 30GiB を超えそうなら、ユーザーの承認が要る（AGENTS.md）。
- merge・push・branch や worktree の削除・外部への送信は、ユーザーの承認を得てから行う。worktree を消す前には `git -C <wt> status --ignored --short` と `du -sh <wt>` を確かめる。
- yfinance の日本の ETF・株には誤りが多い（配当の日付のずれ、分割の未記録、営業日の欠け）。Adj Close を信じない。詳しくは §2 の知識ノート。
