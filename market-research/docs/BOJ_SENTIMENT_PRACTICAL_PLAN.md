# 日銀会合センチメント分析の実務化計画案

更新日: 2026-11-16

状態: 計画案。分析コード・モデル・公開先はこの計画では変更しない。利用先と確認者については回答待ちのため、個人の調査補助から始める案と、業務利用・複数人確認へ進む条件を併記する。

## 目標と現在地

第一目標は、日銀文書を読む人が「今回どこが変わり、どう読め、何がまだ判断できないか」を原文まで追える調査補助である。最終的なレポートの判断・確定は人が行う。次回金利の予測や売買への応用は、別の評価と採否判断を必要とする後段の研究にする。

| 段階 | 状態 | 根拠・残り |
| --- | --- | --- |
| 現行の可視化 | 完了 | 2025〜2026年15会合、政策219段落、原文・英訳・BERT出力・金利履歴・スマホ向けPageがある |
| 現行版の点検 | 完了、修正は未実施 | Fable 5.2 highのレビューで、基準日指定、固定見出し、ラベル整合検証、精度注記の課題を確認。集計15会合の再照合と関連27テストは成功 |
| 実務化の設計 | 今回の提案 | 下記の最小版、評価データ、採用条件、運用手順を段階化 |
| 日銀での性能検証 | 未着手 | 独立した専門家ラベル、校正、変更点の見落とし評価、将来会合での検証が必要 |
| 予測・自動確定 | 未着手 | 調査補助の成績と混同しない。最小版の完了条件には含めない |

既存のCodexによる92段落の読解は、点検例と開発用の補助情報であり、人が独立して付けた正解データではない。[現行の仕様と制約](BOJ_SENTIMENT.md)、[これまでの実装計画](BOJ_SENTIMENT_PLAN.md)も参照する。

## 進め方の比較と推奨

| 案 | 利点 | 課題 | 判断 |
| --- | --- | --- | --- |
| 現行英語BERTに補正ルールを追加 | 既存結果を最も早く改善できる | 否定・文脈依存・日英のニュアンス差を個別ルールだけでカバーし続ける負担。利用条件の確認も必要 | 回帰比較用の基準として保持 |
| 原文比較と人の確定を先に整え、BERTを独立評価して強化 | ユーザーが重視する微妙な変化を検証でき、誤りを原文で訂正できる | ラベル付けと変更点の評価に、人の時間が必要 | 推奨する段階的な案 |
| LLM中心の判定から金利予測までを一体化 | 柔軟な読解・説明を作りやすい | 出力の変動、過去の出来事に関する知識、根拠の検証、予測の評価が一度に増える | 読解支援の比較対象に留める |

推奨案ではBERTの原出力を残し、原文に基づく読解、人による訂正、最終確定を別々に記録する。BERTの再学習は、最小版の利用と評価データ整備の後に採否を決める。

最初のレポートは「今回の要点、前回からの重要変更、方向とペースの評価、判断が割れる箇所、段落別の原文・根拠、過去の推移」の順にする。速報性と再現性のため、公表時点の版と人が確定した版を区別し、スマホでも原文へ戻れる形を維持する。

## 最初に作る確認付きの最小版

既存15会合を使い、次の内容を一画面から確認できるようにする。最初はモデルの追加学習を必須にしない。

1. 今回の原文、出典、会合日、公表日時、取得した版。
2. 同じ論点を扱う前回の候補と文字差分。候補は複数・対応なし・新規論点を許す。
3. BERTの元判定と、根拠を添えた人の確定欄。不明・混在・確認待ちを中立に押し込めない。
4. 条件や否定が変わった部分、重要な追加・削除、対立する意見。
5. 旧版との対応、公表時点、資料の欠損や訂正を見落とさない履歴。

「日銀文学」の文字の変化を読むため、決定文の前回差分も早期に加える提案とする。決定文は当日版、「主な意見」は後日版として分離する。展望レポートの基本的見解や総裁会見は次の拡張候補であり、最小版へ無制限に広げない。

「主な意見」は発言者自身の要約を議長が項目ごとに編集する文書である。前回との類似段落を同じ委員の発言とみなさず、段落比率を委員数・票数に読み替えない。[日銀資料の注1](https://www.boj.or.jp/mopo/mpmsche_minu/opinion_2026/opi261030.pdf)

## ラベルを作り直す方針

主表示は、参照基準の曖昧な単一のタカ・ハト指数だけに依存させない。初期の確定項目を絞り、必要な軸を利用しながら増やす。

| 項目 | 初期の扱い |
| --- | --- |
| 政策手段 | 短期金利、国債購入・YCC、ETF等を区別。違う手段を金利方向へ一律変換しない |
| 提案行動 | 引上げ・据置き・引下げ・行動提案なしを原文根拠とともに記録 |
| 条件・否定・対象時点 | 引用箇所を保持し、今回の決定と将来の条件付き提案を区別 |
| 混在・保留 | 複数の方向や解釈未確定を残し、中立とは別にする |
| ペース・時期の強弱 | 初期は根拠付きのメモ。重要な例で一致して読めることを確認して構造化 |
| タカ・ハト・中立 | 現行BERTの三分類を比較用に保持。新たな派生判定の参照基準と集計規則を別途固定 |

例えば、将来の利上げを支持しながら急ぐ必要はないとする意見は、「引上げ方向」と「ペース慎重」の両方を残す。据置き支持を常にハト派とする、金融環境が緩和的という記述をそのまま緩和支持とする、といった一律の読み方を避ける。市場予想との差は、文書自体の行動提案とは別の変数である。

前回比は同じ論点の候補を読んで、方向、時期・ペース、条件、景気・物価への確信のどこが変わったかを根拠付きで記録する。追加・削除や語句変更だけでタカ化・ハト化と決めず、明確な変化なし・対応不能・解釈保留も許す。景気・物価判断は行動提案と分け、改善や上振れを機械的に利上げ支持へ変換しない。

文・節へ分ける場合も親段落を保持し、否定、条件、引用、前後の文脈を切り落とさない。意味単位への分割自体も人の間で照合する。

## データと対象期間

初版は既存15会合と、現行の短期金利を主に読む枠組みに対象を絞る。過去の拡張は政策制度を区分して行う。

- 2016年以降の長期履歴は後段へ段階的に追加する。90会合前後という件数は見積りであり、臨時会合を含め公表一覧で確定する。2016年の公表一覧には2015年12月会合の資料もあるため、掲載年と会合年を区別する。[日銀の2016年一覧](https://www.boj.or.jp/mopo/mpmsche_minu/opinion_2016/index.htm)
- 負金利、YCC、購入額を中心とする時期を同一の金利指標へ無理に接続しない。目標がレンジなら上下限を保持し、欠損をゼロにしない。
- 会合、決定、公表、適用開始、取得・訂正の日時を分ける。過去の正確な公表時刻が確認できない資料は不明とし、分単位の市場反応分析には使わない。
- 原本URL、ハッシュ、版、抽出器・モデルの版、入力と出力の対応を保存する。日英対応と段落数だけでなく、否定や条件、節境界の保持を点検する。
- 欠損や不一致は停止・要確認とし、前回値を最新結果として黙って表示しない。

現在の処理には日本語PDFと英語PDFの抽出・対応機能が既にある。古いレイアウトへの対応は追加検証の仕事であり、日本語抽出をゼロから新設する計画ではない。

## 正解データとモデルの評価

### 人による判定を先に整える

最初の30単位で、分割・ラベル・根拠引用にかかる時間と解釈の割れ方を実測する。その結果で、200〜300単位の予備判定と追加500〜800単位の要否・工数を見直す。件数は事前に全て集めるノルマではない。

確認者が2人いる場合は、モデル出力を隠して独立判定し、不一致を裁定する。人同士の一致度とクラス別の不一致を示す。不一致率をそのままモデルに許される誤り率とはしない。

本人1人の場合も、原文を確認して使う補助として前進できる。時間を空けた再判定は安定性の点検に使うが、独立した正解との一致や第三者検証とは呼ばない。この状態で自動確定へ進めない。

規約づくりに使った例は開発用である。評価用の会合とラベルは、規約を凍結してから別に確保する。将来の実際の決定を知っていることを、文章の正しい読みの根拠にしない。原文引用で判定を説明できるようにする。

### 評価対象を混同しない

| 評価 | 確認すること |
| --- | --- |
| 文の読解 | クラス別precision/recall、macro-F1、タカ・ハト方向の反転、否定・条件・文脈・手段別の誤り |
| 前回比較 | ツールを見ずに人が作った重要変更点リストとの照合、対応候補の妥当性、見落としと誤った変更判定 |
| 確率・保留 | 必要に応じたBrier scoreや校正、保留に回した後の精度とカバー率。softmaxを正解確率と呼ばない |
| 業務の助けになるか | 重要な人の修正件数、確認時間、出典に戻れるか、納品までの所要時間 |
| 次回政策の予測 | 次の会合を予測する専用の課題。上の読解精度・同会合の決定との一致とは別に評価 |

既存2025〜2026年の資料は既に繰り返し見ているため、未見テストと呼ばない。会合単位・時間順で分割し、同じ会合の文を学習と評価へ混ぜない。近似重複の定型文と新規・変更文の成績を分ける。既知の難例は回帰検査に使い、その正答だけを一般化性能としない。

最終評価の候補は、規約やモデル選択に未使用の会合を追加した段階で確保する。過去の別期間での評価は将来への検証とは区別し、前向きの検証は固定版を使うM4で行う。性能値は件数とクラス内訳を併記し、段落同士の依存を考慮して会合単位の不確実性も確認する。

モデルは多数派固定・辞書などの単純な基準、条件の合う日本語BERT、現行英訳BERT、LLM補助を比較する。既存BERTは利用条件に合う範囲の参考比較に限定する。微調整は、単純な基準からの改善と実際の修正負担の低下が確認できる場合にだけ拡大する。

調整・モデル選択は評価用データの結果を繰り返し見て行わない。確率校正を行う場合も、調整用と最終評価を分ける。温度スケーリング等は手法の候補であり、日銀での有効性を前提にしない。[校正手法の原論文](https://proceedings.mlr.press/v70/guo17a.html)

作業時間の比較では、同じ人が同じ文書を二度読んだ学習効果を改善量に混ぜない。複数人なら別会合を使った割当てを検討する。本人1人や少数会合の観測は、因果的な時間短縮ではなく記述的な利用記録として報告する。

## 採用条件と段階

| 段階 | 作業と成果物 | 通過条件 |
| --- | --- | --- |
| M0 用途と土台 | 確認済み不具合の修正、利用条件・対象範囲・確認者・費用上限の整理 | 基準日の指定が効き、見出しがデータと一致。引用・入力・モデルの対応が追える。未確認の利用条件を実務採用済みとしない |
| M1 確認付き最小版 | 既存原文、前回候補と差分、BERT参考値、人の確定と保留、決定文の単純差分 | 出典引用の文字一致を自動検査。人が判断を訂正でき、重要な見落としを列挙できる |
| M2 規約と評価データ | 30単位の時間計測、予備判定、規約凍結、別会合の評価ラベルと変更点リスト | 独立確認の有無を明記。一致しない軸は自動化対象にしない。規約変更に使った例を最終評価へ流用しない |
| M3 モデル比較・必要なら学習 | 日本語BERT等と単純基準の比較、誤り分析、必要に応じた微調整・校正 | 評価指標と対象範囲を先に固定。新規・変更文と重大反転を含め改善を確認できない場合は参考表示を継続 |
| M4 継続運用 | 固定版で3〜6会合の並行利用。取得障害、訂正、修正負担、重要変更の見落としを記録 | 重大な見落としは原因と対応を全件確認。少数会合の率だけで高精度を主張しない。人が最終確認する運用を維持 |
| M5 予測研究 | 公表時点から次回決定を予測する別データ・評価・必要なら市場織込み | 金利不変・前回判断等の基準と比較。利上げ等の少数事例を過大評価しない。市場データの条件・費用を確認してから着手 |

M0で直す既知の項目は、履歴生成の `--as-of` の反映、入力に応じた見出し・日付・目盛り、確率から導いた分類ラベルとの照合、図付近の精度未検証注記である。現在の15会合で集計が一致したことと、別の入力や基準日でも正しく動くことを分けて確認する。

最初の段階では全件を人が確認する。自動確定の採用は別の判断とし、対象、誤りの損失、保留の割合、統計的な不確実性を含む基準を事前に定める。便宜的な「正解率80%以上」だけで実務利用可能とはしない。

同会合の決定を後日公表の主な意見で説明できることは、事前の予測力を意味しない。市場の織込みとの比較ができない場合は、市場予想を上回る情報価値を立証したとはしない。

## 利用条件とモデル候補

現行cbsentのモデルカードはFed・カナダの英語文書を対象とし、否定表現と文脈依存の制約を明記する。日銀文学でこの弱点がどの程度影響するかを独立評価し、許容できなければ採用しない。重みはCC BY-NC 4.0で、コードのMITライセンスとは区別される。[cbsentのモデルカード](https://huggingface.co/Woochachino/cbsent)

業務利用では、利用先に合う重みと学習データを選ぶ。例えば日本語BERT v3はモデルカード上Apache-2.0の候補だが、日銀向けの性能は未評価であり、微調整データ等の条件も別に確認する。[日本語BERT候補](https://huggingface.co/tohoku-nlp/bert-base-japanese-v3)

日銀原文の転載・加工、成果物の共有先、専門家ラベルの扱いも確認し、新しい全文公開や外部共有をこの計画だけで実施しない。

## 工数・資源と未確定事項

- 確認付き最小版の開発は1〜2週間を仮置きする。モデル再学習や長期履歴の全面対応を含めない。
- 独立評価まで含む実務β版は8〜14週間を概算の計画枠とし、確認者を確保でき、対象を絞れることが前提。最初の30単位の実測で組み直す。現時点の見積りで、品質到達や期日の保証ではない。
- 予備200〜300単位を2人が各2〜4分で読むだけでも約13〜40時間。多軸判定・根拠引用・不一致裁定・前回比較の正解作り・追加データを含めると50〜100時間を超え得る。追加分を固定ノルマにせず必要量を実測で決める。
- 3〜6会合の運用評価には別途数か月を要する。少ない利上げ・利下げ事例を埋めるために、疑似データを実際の会合として扱わない。
- 長期履歴を含む原本・テキストは100MB未満を当初見積りとし、取得時に測定する。モデルは既存キャッシュを共有し、最良の重み・設定・入力ハッシュ・最終結果を保存する。再生成できる大量の中間配列は残さない。
- GPU、学習時間、追加依存、有料データの費用は候補選定後に見積り、必要な承認を得てから使用する。現行の共有環境や公開範囲を計画段階で変更しない。

利用先と第二の確認者については回答に応じて分岐する。回答前でも、個人の原文確認付きツールの計画は成立する。業務向けの採用可否と独立精度の主張は、必要な条件を満たすまで保留する。

## レビューで変えた点

2026-11-16にFable 5.2 highで計画を点検し、再学習より先に前回比較と人の確定欄を作る順序、規約改訂用と評価用の分離、30単位の工数実測、確認者1人の場合の限界を反映した。

追加のOpus maxによる実装者視点の点検は、完了結果を取得できなかったため、レビュー済みの根拠に含めていない。計画の採用時には、対象範囲と確認者の分岐を確定し、実装前に残る論点を再点検する。

日本語PDFの抽出を新設する必要があるという指摘は、既存実装に抽出機能があるため採用していない。人同士の不一致率をモデルの許容誤り率へ直接置き換える案も採用せず、独立した評価指標と用途別の採用条件を設定する方針とした。
