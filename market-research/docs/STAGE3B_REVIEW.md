## 修正

| 指摘 | 対応と回帰テスト |
|---|---|
| J-Quantsの正常なnull行で全期間が失敗 | `PriceGap` として保存し、価格と分けて `no_trade` を返す。正常日との混在・全日無約定・再openを検証 |
| 取得中に閉場すると古い値が確定足になる | 取得開始時点で確定判定。開始は閉場1秒前、完了は1秒後のテストで非確定を確認 |
| 翌日再開で保存済みページの値が確定足になる | ページごとの開始/完了時刻を保存。翌日も元のobserved_atと非確定を保持するテスト |
| 暗号資産の日足session_dateが翌日 | UTC日足の開始日を保持。取得元の2026-09-24日足が09-24となるテスト |

修正前に5ケースの失敗を確認し、修正後はmember suite 86件成功。
レビュアーの最終判定は「重要2件の修正後に可」。修正は失敗→成功の回帰テストと全suiteで確認し、再レビューは行っていない。

## 実装判断

- DuckDBのTIMESTAMPTZ読取は、member単独環境で `pytz` が必要だったため、既存workspace依存を明示。
  依存バージョンは変更していない。判断が不要だった場合の費用は小さなruntime依存1件。
- キャッシュキーに要求期間・取得元記号・確認済み時間表を追加。同一銘柄の別条件のキャッシュを使う誤りを防ぐ。
  費用はmanifestサイズの増加と任意API引数1件。
- 日付ずれはレビューではMinorだったが、公開CLIの利用者が日付結合を誤るためImportantへ変更して修正。
  互換性上、暗号資産の日足 `session_date` は終了日から開始日へ変わる。足のUTC境界は変わらない。

## レビュー対象外の扱い

| レビュアーが判断を保留した事項 | 今回の判断・未確認時の影響 |

| J-Quants実認証・契約範囲、Stooq稼働 | fixture検証とライブ可用性を分ける。[DATA](DATA.md)の未検証/取得不可を維持。実際の利用可能範囲は今後の疎通次第 |
| 手動カレンダーの市場情報 | 指定日不在・市場不一致は拒否。休日/短縮日の根拠は入力者が確認する。誤った時間表は誤った確定判定につながる |
| 外部マクロ/財務、自動カレンダー、画面、旧入口移行 | [STATUS](STATUS.md)の後続範囲。今回を工程3b全体の完了とは扱わず、その機能はまだ使えない |

| 既存二重lagと回復日の警告 | 今回は変更せずSTATUSの既知事項を維持。属性消失と余分な警告の制約は残る |
| キャッシュ文字列正規化・全時間表hash・複数writer・raw残骸 | 明示条件のキー、単一writer、rawの自動削除なしを維持。別表記や時間表変更による余分なcache missと未参照rawの増加はあり得る |
