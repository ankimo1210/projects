# BOJ paragraph sentiment report — implementation plan

> 実行: このセッションで順に実装し、最後に独立レビューを行う。

**Goal:** 2025年の「主な意見」8会合について、日本語原文と段落別のタカ派・ハト派・中立判定を閲覧する自己完結HTMLを作る。

**Architecture:** 日本銀行の日本語・公式英訳HTMLを保存し、節と段落の順序で対応を照合する。金融政策向けModernBERTを固定revisionでローカル実行し、3分類のsoftmaxと判定を保存する。HTMLは既存claude-reportテンプレートを使い、保存結果から通信なしで再生成する。

**Tech stack:** Python、既存PyTorch、一時実行環境のTransformers、標準ライブラリ、HTML/CSS/JavaScript。

**Spec:** ユーザーが承認したチャット内設計（2026-11-10）。原文・判定・3分類出力、会合別割合、会合/分類フィルタ、前後の文脈。

## Global constraints

- 作業範囲はmarket-research。既存アプリ、共有環境、依存宣言、lockfileを変更しない。
- 保存データは `_data/market-research/boj-sentiment-2025/`。モデル重みは通常のHFキャッシュを使い、複製しない。
- 主集計は「金融政策運営に関する意見」。経済・物価は別区分、政府意見は表示のみで主集計に混ぜない。
- 段落数の不一致、欠損、非有限スコア、想定外ラベル、入力上限超過は処理を停止する。入力を黙って切り捨てない。
- 出力はモデルによる試験分類。日銀での正解率、政策委員の人数、利上げ確率と解釈しない。
- 外部公開・push・コミットは行わない。既存ブランチ上の新規ファイルを中心に作業する。
- 見積り: HTML原本16本は約2 MB、JSON/HTML/検証画像は合計10 MB未満。モデルは約440 MB、推論はFP32・batch 8・512 tokens以下でCPU RAM/GPU RAMとも数GB程度。30 GiB未満。

## Review focus

1. 日英の段落対応ずれを同数という理由だけで見落とさない（節・数字・全段落の目視照合）。
2. 中立とモデルの迷いを混同しない（低marginを独立表示）。
3. 政府意見・経済判断を政策委員会の総意として集計しない。
4. 長文・否定・条件節の読み違いを、原文と英訳で点検できる。
5. 保存結果の再生成が新しい通信・モデル再推論を要求しない。
