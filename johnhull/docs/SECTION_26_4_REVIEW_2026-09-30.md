# §26.4 Gap Options：原典照合と受入範囲

日付：2026-09-30。対象は Hull 11e Global Edition p.617（式26.1・26.2、例題26.1）。
§26.3 と同じ5軸（説明、実装、独立検証、可視化、実画面）で GP01–GP06 を確認する。
原典が数値を挙げるのは例題26.1（$S_0=500{,}000$、$\sigma=20\%$、$r=5\%$、$q=0$、$T=1$）だけで、
行使価格400,000の通常のプット **3,436**、$K_1=400{,}000$・$K_2=350{,}000$ のギャップ・プット **1,896**、
「約45%」の減少である。それ以外の市場（$S_0=100$ など）と移転費用の曲線は合成例で、原典の記述ではない。

| 要求 | 原典・実装・検証の位置 |
|---|---|
| GP01 支払の定義 | コールは $S_T>K_2$ で $S_T-K_1$、プットは $S_T<K_2$ で $K_1-S_T$。$K_2$ が支払の条件（トリガー）、$K_1$ が支払額。$\max(\cdot,0)$ で抑えないので、$K_1>K_2$ のコールは $K_2<S_T<K_1$ で負。$K_2$ で $\lvert K_2-K_1\rvert$ だけ跳ぶ。`GapOption.payoff` と保存参照の支払表で照合。 |
| GP02 式26.1・26.2 | $d_1,d_2$ はトリガー $K_2$、現金の項だけ $K_1$。公開 API `hullkit.gap_options.gap_option` は `hullkit.exotics.gap_call`/`gap_put` で価格を出す。独立参照（erfc の閉形式と対数正規の求積）と38ケースで相対差 $4.3\times10^{-15}$ 以下。 |
| GP03 通常のオプションとの差 | $c_{\text{gap}}=c(K_2)+(K_2-K_1)e^{-rT}N(d_2)$、$p_{\text{gap}}=p(K_2)+(K_1-K_2)e^{-rT}N(-d_2)$。差は符号付きのキャッシュ・オア・ナッシング（§26.10）。パリティ $c_{\text{gap}}-p_{\text{gap}}=S_0e^{-qT}-K_1e^{-rT}$、$K_1=0$ は資産・オア・ナッシング。価値ゼロの $K_1$ はトリガー条件付きの $S_T$ のリスク中立平均（合成市場でコール123.4819、プット82.7715）。 |
| GP04 例題26.1 | 通常のプット 3,435.95、ギャップ・プット 1,895.69、減少 44.83%。四捨五入で印刷値 3,436・1,896・約45% に一致。 |
| GP05 保険会社と契約者 | 契約者の手取りは $350{,}000-S_T$ で、価値は行使価格350,000の通常のプット 630.79（原典にない補足）。保険会社の費用との差 1,264.90 は請求時の移転費用の現在価値 $50{,}000e^{-rT}N(-d_2)$、$N(-d_2)=2.66\%$。移転費用0〜150,000の曲線は同じ市場の合成。 |
| GP06 適用範囲 | 定数 $r,q,\sigma$ の BSM、欧州型、満期でだけトリガーを判定。契約者は手取りが正なら請求すると仮定。取引費用、保険会社の信用リスク、離散配当、$K_2$ 付近のヘッジは対象外。練習問題5問。 |

**独立参照。** `scripts/build_gap_reference.py` は標準ライブラリと numpy だけを使い、`hullkit` を import しない（AST で検査）。

1. 式26.1・26.2 を `math.erfc` の正規分布関数で自前実装する。$K_1=K_2=100$、$\sigma=20\%$ の通常のコール 10.4506 も再現する。
2. 支払を対数正規密度で求積する。Gauss–Legendre 32点×96区間、トリガーを区間の端点に置き、$\pm16$ 標準偏差まで積分する。38ケースで閉形式と相対 $10^{-10}$ 以内（実測は絶対 $5.1\times10^{-12}$ 以下）。
3. モンテカルロは10ケースで、ケースごとに別のシード（20260930+i）、$2^{19}$ 組の反対変量、許容は4標準誤差。実測の $\lvert z\rvert$ は最大1.58。例題のギャップ・プットは標準誤差が11.45（価格の0.6%）なので、精密な照合は求積が担う。
4. 例題26.1 は印刷値の四捨五入と一致しなければ参照の生成自体が失敗する。

**可視化と検査。** Book と portal で次の4図を共用する。

- 満期の支払（$K_1=90$・110、$K_2=100$。跳びの片側極限を白抜きの丸で示す）
- $K_1$ と価格の直線（コールとプット、$K_1=K_2$ の通常のオプション、価値ゼロの $K_1$）
- 例題26.1 の保険会社の費用・通常のプット・契約者の手取り
- 移転費用と保険会社の費用・契約者の価値・移転費用の現在価値

Browser 検査は4図×2画面×2幅（1440/1000px）で16状態・16スクリーンショット。Book の数式898個の表示エラーは0で、数値の改変は拒否される。ノートブックは169セル（§4.11 の11セルと、M20 基点と一致するそれ以外の158セル）で、負の対照4件を拒否する。数値ゲートは保存データの改変5件と、公開 API 側の改変3件（$d$ を $K_1$ で計算、プットの $K_1$・$K_2$ の入れ替え、相対 $10^{-9}$ のずれ）を拒否する。

**公開 API の置き場所。** 入力検証は新しい `hullkit.gap_options` に置き、`hullkit.exotics.gap_call`/`gap_put` は変更しない。`exotics.py` は既受入4節（§26.12–§26.15）の保存データがハッシュで固定しており、変更するとそれらの証跡を作り直す必要がある。さらに `hullkit/__init__.py` の静的 import を通じて既受入全節の D1 依存指紋に入るので、変更すると全節の再描画にもなる。また `gap_options` は `hullkit/__init__.py` に登録しない（`from hullkit import gap_options` で使う）。`__init__.py` は既受入全節の D1 依存指紋に入るので、登録すると20節すべての再描画が必要になる（M19・M20 はこの理由で全節を再描画した）。§26.1 の `packages` と同じ扱い。

**独立レビュー。** 実装の外から原典・コード・本文・図・検査を読み直したレビューで、P1 は0件、P2 は2件、P3 は複数の指摘があった。数式と例題26.1 は 50桁の独立計算で一致し、API の分解・パリティ・$K_1=0$・価値ゼロの $K_1$ も正しかった。

P2 の2件：

- **負の対照が API 比較を通っていなかった。** 5件の改変はすべて保存データの再計算照合で落ち、API と参照の許容差の判定は一度も試されていなかった。公開 API 側を壊す3件の対照を加え、記録に残した。例題の照合は $K_1$・$K_2$・移転費用を保存データから読むようにした。
- **原典の書き方の要約が不正確だった。** 本文は「原典は『大きい』と書くが、それは $K_2>K_1$ の場合」と書いていた。原典は直前の括弧書きで増分が正にも負にもなることを断っている。原典の注記どおりに書き直した。

P3 への対応：

- 本文のパリティ誤差は、参照内の恒等式ではなく、そのセルで公開 API から計算して表示する。
- 「第三者へ払われる」は原典にない解釈なので、支払先は原典に書かれておらず、保険会社も契約者も受け取らない費用と読める、と本文に書いた（portal カードは最終レビューで直した）。契約者の価値 630.79 は補足と明記した。「右の図」を「下の図」に直した。
- 練習問題4の答え（移転費用100,000で382.18）を本文とコード出力から外した。
- 本文の数値（傾き、15.8609、11.1238、123.4819、82.7715、2.66%、44.83%）を保存参照と照合するテストを加えた。
- portal のカードに、プットの傾き、「保有者が受け取る額は負（保有者が払う）」、移転費用の曲線は原典の2点以外が合成であることを書いた。
- 跳びの片側極限を白抜きの丸で示した。支払ゼロの区間で線が重なって見えなくなる点は、値が同じなので凡例で区別し、そのままにした。
- API：価格の桁あふれを `ValueError` にした。`K1=0` のプットが資産・オア・ナッシング・プットの売りであることを docstring に書いた。`carry_forward` を `forward` に改名した。実数以外の入力には「finite real number」と伝える。
- テスト：同じ関数どうしの自明な比較を外し、参照が `hullkit` を import しないことを AST で検査するテストを加えた。

**最終レビュー。** 受入後のブランチ全体（受入ツール・台帳・文書を含む）を別のレビュアーが読み直した。P1・P2 は0件、P3 は9件。台帳の更新は基点から再生成するとバイト単位で一致し、D1 の reuse 判定、公開 API 側の負の対照、本文の数値も独立に確かめられた。P3 はすべて直した。

- portal カードに「第三者に払われる」が残っていた。本文と同じく、支払先は原典にないと書いた。
- $S_0<1$ で $(r-q)T$ が大きいと、先渡し価格の計算が素の `OverflowError` になった。対数で計算するようにし、テストを加えた。
- 上限値の表記（$5\times10^{-12}$、$4.2\times10^{-15}$）が実測値をわずかに下回っていた。$5.1\times10^{-12}$、$4.3\times10^{-15}$ に直した。

- README の M20 の段落が現行の検査を指していた。現行は `verify_gap_notebook.py` と D1 記録だと書いた。
- `exotics.py` を変えない理由に、全節の依存指紋に入ることを加えた。
- 凡例の助詞（「K2 を上から近づく」）を直した。
- ROADMAP のモジュール数（基点から1ずつ少なかった）を実数の66・21に直した。
- 統合記録は各節の最新の D1 記録を採るが、それが M21 のコミットで作られたかを確かめていなかった。M20 基点より後のコミットであることを確かめる検査を加えた。

`figures.py` の変更で既受入20節の D1 記録が古くなるので、D1 を再実行した。20節とも reused（新規保存0バイト）で、§26.3 は最初の実行で作った redrawn 記録を基点にした。

**適用範囲。** BSM の欧州型ギャップ・オプションで、$r,q,\sigma$ は定数、トリガーは満期でだけ判定する。取引費用、保険会社の信用リスク、離散配当、$K_2$ 付近のデルタの振れとヘッジ誤差は対象外。例題26.1 以外の数値は合成例である。
