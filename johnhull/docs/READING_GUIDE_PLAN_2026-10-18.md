## 2. 方針（推奨）

**新しい「章ごとに読むガイド」を Book に足す。既存の notebook と補足教材の本文は変えない。**

- 理由：既存の本文は全306節の受入証跡（説明・表示の verified）に固定されている。書き換えると、変えた章の証跡を再検査しなければならない（fast-v1 の章ごとの再検査、Ch26–27 は D1 の再描画）。新しいページなら節の証跡に触れない。
- ガイドから既存の計算セル・補足教材の節へリンクし、「読む→計算で確かめる」の順に読めるようにする。
- 既存本文の書き換えは別判断とする（§7 の決定事項1）。

### 置き場所

- 本文：`johnhull/book/notebooks/guide/chNN.md`（MyST Markdown、コードは実行しない）。37ページ＋用語集1ページ。
- Book：`book/_toc.yml` の先頭（コア巻の前）に部「Hull 11e を章ごとに読む」を足し、`00_overview.md` から入口を張る。

## 3. 1章のページの型

| 部分 | 書くこと |
|---|---|
| この章の問い | 章が答える問い。前の章のどこから続くか。前提にする章 |
| 舞台と登場人物 | 商品・市場・使う人と目的。用語と記号（単位つき） |
| 節ごとの解説（Hull の節順） | その節の主張 → なぜ成り立つか（裁定・複製・期待値の論理を言葉で） → 式の各記号の意味 → 例題の数字の追い方 → よくあるつまずき |
| 一般的なストーリー | 歴史的経緯、実務での使われ方、業界での受け止め。出典と時点を付ける |
| 計算で確かめる | Book の該当巻・セル、補足教材の節へのリンク |
| まとめと次の章 | 3〜5文。次の章で何に使うか |
| 確認の問い | 自作の問い。章末問題の解答は扱わない |

## 4. 書き方の規則

- 地の文で書く。1段落に1つの論点。電報文や略語の羅列にしない。
- 英語の用語は初出で「日本語（English）」と書き、略語は初出で定義する。訳語は用語集で統一する。
- 記号は初出で意味と単位を書く。式の前後に、式が何を言っているかを文で書く。
- 数値は、台帳・hullkit のテストで固定済みの値だけを使う。新しい数値を出すときは計算で確かめ、確かめたセルかテストを示す。
- **原典の文章を訳して並べない。** repo は PUBLIC で、Hull の本文は著作物である。要約・言い換え・独自の例えで書き、引用は短い語句に限って頁を付ける。図表は再掲せず、番号と頁で参照する。
- 原典は Global Edition（節・図番号・例題数値が US 版とずれる）。頁と節番号は毎回 PDF と照合する。
- 時点で変わる話（LIBOR の終了、Basel・FRTB、清算義務など）は「刊行時点の記述」と「現在（確認日つき）」を分け、現在側は一次資料で確認する。
- 「一般的なストーリー」は出典のある通説に限る（Hull 本文、標準的な教科書、当局・取引所の資料）。出典のない逸話は書かない。

### 各便の検証

1. 原典との照合：各節の主張に頁を付ける。独立レビュー（新しいエージェント、GE PDF を読む）が、主張・数値・頁と、原文の翻訳になっていないかを確かめる。
2. 数値：ガイドに出す数値の一覧（値・出典の台帳項目またはテスト）を章ごとに残し、レビューで照合する。
3. 読みやすさ：レビューが初学者として読み、分からなくなる箇所を挙げる。直してから受け取る。
4. 表示：`make hull-book` で Book を作り、数式（MathJax）・リンク・幅1280と狭い幅のはみ出しをブラウザで確かめる（Playwright は 1.56.0 固定）。
5. 回帰：`make lint`、`make test`（単一スレッド BLAS）、`make hull-release-check`、共有ランタイム検査。
6. `ROADMAP.md` の「現在地」と「完了までの計画」を同じコミットで更新する。
