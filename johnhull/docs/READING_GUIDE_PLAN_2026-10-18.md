### 3.1 モデル地図（T2）

既存の索引は探すための表で、モデルの中身と関係は読めない。`MODEL_INDEX.md` は英語のエージェント向けで、関数名・テスト・巻を対応させる。`CONTENTS_INDEX.md` は巻ごとの収録モデルと短い案内で、Book には載っていない。モデル地図は読者向けに、モデルの一覧・中身・関係を Book の1ページで見せる。

| 部分 | 書くこと |
|---|---|
| 地図の読み方 | 系統の分け方、矢印の種類、カードの読み方 |
| 系統ごとの図 | BSM と木・数値手法／ボラティリティ（局所・確率・ジャンプ）／金利（短期金利・HJM・LMM）／信用（構造型・強度型・コピュラ・XVA）／リスク計量（VaR・EWMA・GARCH）／Beyond Hull の6系統。系統で絞り込み、拡大して読む |
| モデルカード | 名前（日本語・English・略称）、何を表すか（状態変数と単位）、主な仮定と崩れたときに困ること、解き方（解析解・木・PDE・MC）、使う商品・場面、関係する相手と矢印の種類、読む場所（Hull の章節・各章のガイド・Book の巻・補足教材）、実装と検証の範囲（`MODEL_INDEX.md` の該当する節へ） |
| 問いから選ぶ早見表 | 「この商品・この問いにはどのモデルか」の表（例：米国型プット→二項木・LSM・有限差分）。各行からカードへリンクする |

- 対象は `MODEL_INDEX.md` のモデルの行すべてとする（決定、2026-10-18、ユーザー：推奨の40〜60個より増やす）。§1〜14 の約110行と、P3・P4 の logic-first の約67行が対象。§15 のインフラと研究（RB-F*）の節は除き、同じモデルが重なる行はまとめる。行数に落としたのは Claude。
- 矢印は3種類に限る。どの矢印にも、式で確かめられる条件と出典（Hull の節か標準的な教科書）を付ける。
  - 特殊な場合：例として、Ho–Lee は Hull–White で平均回帰の速さ a を0にしたもの。
  - 極限・近似：例として、CRR は段数を増やすと BSM に近づく（GE 第13章付録）。
  - 入力・較正：例として、Dupire の局所ボラはインプライド・ボラの曲面から作る。
- カードに新しい数値を出さない。数値例は各章のガイドに任せる。
- 実装の範囲を誇張しない。部分実装は `CONTENTS_INDEX.md` §7 の制限と同じ書き方にする（例：vol 21 の rough Heston は kernel のみ）。
- 図は対話的にする（決定、2026-10-18、ユーザー）。plotly（hullkit の既存の依存）を使い、拡大・系統の絞り込み・クリックやタップでモデルカードへ移る操作を付ける。plotly.js は既存の notebook（vol 13–16）と同じくページに同梱し、CDN を使わない（外部通信0）。graphviz と mermaid は環境にないので使わない。
- 図は、手で座標を決めた定義ファイル `model_map.json` から作る。図の定義（plotly の JSON）は決定的にする（div の id を固定し、日時を入れない）。JS が動かなくても、モデルカードの本文と早見表は読めるようにする。
- 390px の画面で、絞り込みと拡大で図が読めること、タップでカードへ移れることを目視で確かめる。plotly.js を含むページの重さを記録する。
- 鮮度はテストで守る。次のどれかで落とす。
  - 図とカードでモデルが食い違う。
  - 矢印の端点がない。矢印の種類が3種類以外。
  - リンクが切れている（Book の巻と節のアンカー、補足教材、`MODEL_INDEX.md` の見出し）。
  - 定義ファイルから作り直した図の定義が、コミット済みのものと byte で一致しない。
- 各章のガイドへのリンクは、B1〜B6 で章を足すたびに加える。

## 4. 書き方の規則

### ストーリーを最優先にする（ユーザー、2026-10-18）

- 節のつなぎ：各節の冒頭1〜2文で、前の節までで何が分かり、まだ何が足りないからこの節が来るのかを書く。
- 章の筋：「この章の問い」で、問い → 道具 → 答え → 限界という章全体の流れを先に示す。「まとめと次の章」では、次の章が何を引き継ぐかを書く。
- 章をまたぐ筋：`00_overview.md` に、章どうしのつながりの地図（どの章が、どの章の何を使うか）を置く。各章の「この章の問い」から、前の章のガイドへリンクする。
- 筋に要らない式・数値・制度の細部は削る。分量の目安（§7 の2）と筋がぶつかったら、筋を優先する。
- 先の節や章の内容には、筋に必要なときだけ触れる。触れるときは、どこで扱うかを書き、扱う側の節からも戻れるようにする。

### 文と用語

- 地の文で書く。1段落に1つの論点。電報文や略語の羅列にしない。
- 英語の用語は初出で「日本語（English）」と書き、略語は初出で定義する。訳語は用語集で統一し、Book 本体に定着した訳語を使う（[訳語の決定](READING_GUIDE_TERMS_2026-10-18.md)）。
- 記号は初出で意味と単位を書く。式の前後に、式が何を言っているかを文で書く。
- 数値は、台帳・hullkit のテストで固定済みの値だけを使う。新しい数値を出すときは計算で確かめ、確かめたセルかテストを示す。
- **原典の文章を訳して並べない。** repo は PUBLIC で、Hull の本文は著作物である。要約・言い換え・独自の例えで書き、引用は短い語句に限って頁を付ける。図表は再掲せず、番号と頁で参照する。
- 原典は Global Edition（節・図番号・例題数値が US 版とずれる）。頁と節番号は毎回 PDF と照合する。
- 時点で変わる話（LIBOR の終了、Basel・FRTB、清算義務など）は「刊行時点の記述」と「現在（確認日つき）」を分け、現在側は一次資料で確認する。
- 「一般的なストーリー」は出典のある通説に限る（Hull 本文、原論文、標準的な教科書、当局・取引所の資料）。Hull 以外の出典は、主張・年・数値を一次資料で確かめ、出典と時点を書く。出典のない逸話は書かない。

### T3 既存 notebook の表示の整理（ユーザー、2026-10-19）

Book の30冊の notebook にはコードセルが541個あり、描画を含むものが約200個ある（2026-10-19、Claude の概数）。読者にとって意味の薄いコードを、ページから消す。

- 消すもの：matplotlib・plotly の描画、import、設定（`hullkit.nbplot.setup()` など）、表の整形だけのコード。セルの tags に `remove-input` を付けて、入力だけを消す。図・表・数値の出力は残す。
- 残すもの：モデルを呼んで、説明で使う数値を出す短いコード。
- 計算と描画が1つのセルにあるときは、builder で計算のセルと描画のセルに分けてから、描画の側を消す。分けないものは、理由を一覧に書く。
- notebook のソースからは消さない。図を作り直せること、出力の検査が通ることを保つ。
- tags は builder で付ける（`volumes/*/build_*_notebook.py`、`interest_rate_models/build_ir_models_notebook.py`、`scripts/build_frontier_notebooks.py`）。notebook を直接編集すると、次に builder を回したときに消える。builder のない notebook（`15_bsm_ch15.ipynb` など）は notebook を直接直し、その旨を一覧に書く。
- builder を回したら `verify_core_notebooks.py --write-outputs` で出力を作り直し、`make hull-core-notebooks-check`・`make hull-notebooks-check`・`make hull-artifacts-check` を通す。出力の値（stdout・`text/plain`）が変わらないことと、画像の byte が一致するかどうかを記録する。
- Greeks の訳語：vol03 の題と §1 の見出し、vol01 の本文の「ギリシャ文字」を「グリークス」に直す（[訳語の決定](READING_GUIDE_TERMS_2026-10-18.md)§2）。
- 消したセルの一覧（notebook・cell id・消した理由）を `docs/validation/reading-guide/` に残し、レビューで「意味のあるコードを消していないか」を確かめる。
- 証跡：表示が変わる節は、`docs/EVIDENCE_POLICY.md` の「説明や計算や描画に変更」に当たる。T3 に入る前に、D1 記録と台帳の成果物ハッシュが変わる節を数え、再描画の量を見積もる。これは T2 の報告に含める。

### 各便の検証

1. 原典との照合：各節の主張に頁を付ける。独立レビュー（新しいエージェント、GE PDF を読む）が、主張・数値・頁と、原文の翻訳になっていないかを確かめる。Hull 以外の出典は、主張・年・数値を一次資料で確かめる。
2. 数値：ガイドに出す数値の一覧（値・出典の台帳項目またはテスト）を章ごとに残し、レビューで照合する。
3. 読みやすさとストーリー：レビューが初学者として読み、分からなくなる箇所を挙げる。節のつなぎと章の筋が読み取れるか、章をまたぐ参照とリンクが正しいか、訳語が用語集と揃っているかも確かめる。直してから受け取る。
4. 表示：`make hull-book` で Book を作り、数式（MathJax）・リンク・幅1280と狭い幅のはみ出しをブラウザで確かめる（Playwright は 1.56.0 固定）。
5. 回帰：`make lint`、`make test`（単一スレッド BLAS）、`make hull-release-check`、共有ランタイム検査。
6. `ROADMAP.md` の「現在地」と「完了までの計画」を同じコミットで更新する。
