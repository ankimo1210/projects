## 1. 目的と成功の条件

Book（巻・章ごとのガイド・モデル地図）と補足教材を、スマホを含むどの端末からでも読めるようにする。読みながら、その場で計算を試せるようにする。

成功の条件：

1. ログインした本人だけが、スマホと PC で Book・補足教材・計算機を使える。ログインしていなければ、中身は一切返らない。
2. 二項木の計算機が、Hull の例題（GE 第13章）の表示値を既存の固定テストと同じ精度で再現し、ネイティブの hullkit と同じ値を返す。
3. 一度開いたページと計算機は、オフラインでも動く。
4. 将来の公開は、別承認の確認と Access を外す操作だけでできる。サーバも作り直しも要らない。

## 2. 決めたことと、選ばなかった案

| 事項 | 決定 | 選ばなかった案と理由 |
|---|---|---|
| 計算の場所 | Pyodide を使い、ブラウザ内で hullkit を動かす | 計算 API（Fly.io）：運用と費用がかかり、公開時にアクセス制限が要る。TypeScript で書き直す：hullkit との二重実装になり、検証済みの値からずれる |
| 置き場所と認証 | Cloudflare Pages＋Cloudflare Access（Zero Trust の無料枠、50人まで） | Vercel Hobby：本番ドメインを保護できない（Pro が必要）。GitHub Pages：Free では公開しかできず、iOS アプリのサポートページ（`https://ankimo1210.github.io/projects/`）と同居する。Fly.io：認証を自分で作ることになる |
| 画面の枠組み | Vite＋React＋TypeScript | UI フレームワークなし：計算機を足すたびに画面の部品を作り直すことになる |
| Book の組み込み | 既存のビルド結果を、組み立てのときにコピーする | Book に計算機を埋め込む：`_config.yml` と `_static` は共有ランタイムなので、変えると一括検査と manifest の更新が要る。ガイドの branch とも衝突する |

## 3. 構成

### 3.1 repo の置き場所

| パス | 中身 |
|---|---|
| `johnhull/web/` | Vite＋React＋TypeScript のアプリ（`package.json`・`pnpm-lock.yaml`・`vite.config.ts`・`src/`・`public/`・`README.md`） |
| `johnhull/web/py/` | ブラウザ用パッケージの組み立てと、照合用の期待値（golden）の生成（Python） |
| `johnhull/web/tests/` | Playwright の検査（計算の一致・表示・リンク・通信・オフライン） |
| `johnhull/web/dist/` | 組み立てたサイト（Git 管理外） |
| ルートの `Makefile` | `hull-web`（組み立て）・`hull-web-check`（検査）・`hull-web-deploy`（配信） |

Python の検査（パッケージの一致・期待値）は `make test` に入れる。ブラウザを使う検査は `make hull-web-check` に分ける。

### 3.2 サイト内の配置

checkout と同じ相対配置を写す。こうすると、ガイドから補足教材や数値表へのリンク（`../../../../../report/site/...` など）が書き換えなしで動く。

| サイトのパス | 元 |
|---|---|
| `/` | 入口ページ（Book・補足教材・計算機へ） |
| `/book/_build/html/` | `make hull-book` の出力（`_sources/` と `.buildinfo` を除く） |
| `/report/site/` | `make hull-report` の出力 |
| `/docs/validation/reading-guide/` | ガイドが参照する数値表（ガイドの統合後） |
| `/calc/binomial/` | 二項木の計算機 |
| `/pyodide/` | Pyodide の本体、numpy と scipy の wheel、ブラウザ用 hullkit |
| `/sw.js`・`/manifest.webmanifest`・`/_headers`・`/robots.txt` | Service Worker、PWA の定義、ヘッダ、クローラの拒否 |

載せないもの：PDF（教科書・論文）、`_sources/` の .ipynb、`.buildinfo`、作業データ。組み立て後の検査で、これらが含まれないことを確かめる。

### 3.3 ブラウザ用 hullkit

- `import hullkit` すると、`__init__.py` が全モジュールを読み込む。その中には plotly を使う `plotly_viz` も含まれる。
- そこでブラウザでは、使うモジュールだけを、元のファイルとバイト単位で同じまま新しいパッケージに入れる。生成するのは `__init__.py` だけにする。
- 最初の版に入れるのは `trees.py`（numpy だけを使う）と `bsm.py`（numpy と scipy を使う）。
- hullkit 本体のソースは変えない。`python_sources` は D1 の依存指紋に入っており、変えると受入記録の鮮度に響く。
- 検査：パッケージ内の各モジュールの SHA-256 が repo の hullkit と一致すること。生成した `__init__.py` が import 以外を持たないこと。

### 3.4 Pyodide の配信

- 版は計画の段で固定する。条件は、公開から2週間以上たっていること、Python ≥3.12・numpy ≥2.0・scipy ≥1.13 を満たすこと。
- 本体と numpy・scipy の wheel を自分のサイトから配信する。外部とは通信せず、オフラインでも動く。取得するときに `pyodide-lock.json` の SHA-256 と照合する。
- Pyodide と numpy を読み込むのは、計算機を開いたときだけ。scipy は BSM との比較を開いたときに読み込む。読む画面では Pyodide を読み込まない。

### 3.5 二項木の計算機

**入力**

- 木の作り方：u・d を直接指定する（§13.1〜13.5）か、σ から CRR の木を作る（§13.7 以降）。
- 原資産：
  - 配当のない株式（q=0）
  - 配当利回りのある株式・指数（q）
  - 通貨（外国金利 r_f を q に入れる）
  - 先物（q=r とし、a=1 になる）
- 契約：コール／プット、ヨーロピアン／アメリカン。
- 数値：S0（先物では F0）、K、r、q または r_f、σ（または u・d）、T（年）、段数 n（1〜500）。

**出力**

- 価格、p、a、u、d、Δt。
- 木の図（n≤6）：節点ごとの株価・オプション価値・デルタ（`tree_delta`）。早期行使する節点は強調する。
- 収束図：n を変えたときの価格。ヨーロピアンは BSM（`bsm.py`）と比べる。

**例題ボタン**

- 対象：§13.1・§13.3・§13.4・§13.5・§13.8・§13.10、例題13.1〜13.3。
- 計算結果に原典の表示値を並べ、印刷時の丸め（たとえば p を4桁に丸めた値）による差を示す。
- 期待値は既存の固定テスト（`hullkit/tests/test_hull_pins_options.py` など）から取る。新しい値は作らない。

**入力の検査と実行**

- 裁定のない条件（d < a < u、つまり 0 < p < 1）を満たさないときは計算せず、理由を表示する。段数の上限を超える入力は受け付けない。
- 計算は Web Worker で行い、画面を止めない。

### 3.6 読む機能

- Book と補足教材は、ビルド結果をそのまま配信する。サイト内検索は Book の検索を使う。
- **PWA**
  - ホーム画面に追加できる。
  - Service Worker は、アプリの枠を最初に保存する。Pyodide と numpy は計算機を初めて開いたときに、Book と補足教材のページは開いたときに保存する（読むだけなら Pyodide を取りに行かない）。
  - 取得の順序は、HTML はネットワーク優先、静的ファイルはキャッシュ優先にする。
  - 保存するのは同一オリジンの 200 応答だけにする。Access のログイン画面への転送は保存しない。
- **noindex：** `_headers` で `X-Robots-Tag: noindex` を付け、`robots.txt` で全クローラを拒否する。

### 3.7 認証と配信

**Cloudflare Access**

- `*.pages.dev` とプレビューの両方を保護する（Pages の Known issues にある手順）。
- ログインはメールに届く一回限りのコードで行い、許可するのは本人のメールアドレスだけにする。

**順序（公開状態になる時間を作らない）**

1. 本人が Cloudflare のアカウントと、Pages を編集できる API トークンを用意する。トークンは手元の環境変数に置き、repo にも memory にも置かない。
2. Pages のプロジェクトを、中身なしで作る。
3. Access を `*.pages.dev` とプレビューにかける。
4. ログインせずに `curl` し、中身ではなく Access への転送が返ることを確かめる。
5. 中身を配信し、4 をもう一度確かめる。

**配信とヘッダ**

- 配信は `make hull-web-deploy` で行う（`wrangler pages deploy`、npx で版を固定）。毎回、本人の承認を得てから実行する。
- **CSP（Content Security Policy）**
  - 対象は入口と計算機だけにする。`script-src 'self'` と、Pyodide に要る `'wasm-unsafe-eval'` などを付ける。最小限で済むかは W0 で確かめる。
  - Book と補足教材はインラインのスクリプトを使うので、既存の動作を壊さない範囲にとどめる。
- そのほかに `X-Content-Type-Options: nosniff` と `Referrer-Policy` を付ける。

## 4. エラーと劣化の扱い

- Pyodide の読み込みに失敗したとき：計算機に理由と再試行のボタンを出す。読む画面は影響を受けない。
- 計算が長引くとき：Web Worker で実行し、進行中の表示と中止のボタンを出す。
- オフラインで、まだ保存していないページを開いたとき：Service Worker が、オフラインでありこのページは未保存だと表示する。
- Access のセッションが切れたとき：ページを移ると Access のログインへ転送される。Service Worker はこの転送を保存しない。

## 5. 検証

| 検査 | 内容 |
|---|---|
| パッケージの一致 | ブラウザ用 hullkit の各モジュールが、repo とバイト単位で一致する |
| 計算の一致 | 例題と境界の入力で、ネイティブの hullkit と Pyodide の結果が一致する。許容誤差は W0 で実測してから決め、根拠のない余裕は足さない |
| 原典の値 | 例題ボタンの結果が、既存の固定テストと同じ精度で原典の表示値と一致する |
| サイトの中身 | PDF・`_sources/`・`.buildinfo` がない。25 MiB を超えるファイルがない。サイト内の相対リンクがすべて解決する |
| 表示 | 1280px と 390px でスクリーンショットを撮って目視する。外部への通信とページエラーがない。木の図と収束図が画面からはみ出さない |
| オフライン | 一度開いた Book のページと計算機が、ネットワークを切っても動く |
| 認証 | ログインせずに `curl` すると中身が返らない（Access への転送になる）。ログイン後は全ページが開く |
| 回帰 | `make lint`・`make test`・`make hull-release-check` が通る。Book の設定・台帳・hullkit を変えていないことを差分で確かめる |

- ブラウザの検査は、既存の Book の検査と同じ版の Playwright 1.56.0 と Chromium で行う。
- 計測：次の値を記録する。目標値は W0 で実測してから決める。
  - 初回の読み込み量（Pyodide＋numpy のときと、scipy を足したとき）
  - 最初の計算が終わるまでの時間（390px、CPU を遅くした条件）

## 7. 範囲外

- 一般公開。別に承認を得る。公開する前に、Book・ガイド・補足教材が原典の翻訳や図表の再掲になっていないかを確かめ、Access の解除と noindex の扱いを決める。
- 利用者のアカウント、計算結果の保存、サーバ側の処理。
- Book の設定・拡張・静的アセット（共有ランタイム）、節台帳、hullkit 本体の変更。
- 教科書と論文の PDF の配信。

## 8. 引き継ぎ（Sol 向け）

- 着手は、読むガイドの修正の回を終えてからにする。ガイドの branch とは別の worktree と branch（例：`/home/kazumasa/worktrees/hull-web`、`codex/hull-web`）で作業する。
- Git 管理外の作業データは `/home/kazumasa/projects/_data/johnhull/hull-web/` に置く。
- Node は静的 PATH の v26 を使う（nvm は使えない）。pnpm は npx の固定版を `--ignore-scripts` 付きで使う。
- 配信（W2）は、本人の承認と Cloudflare の準備が済んでから行う。トークンを repo・ログ・memory に残さない。
- W0 の結果を報告したら止める。設計を変える必要があるかを本人と Claude が確かめてから、W1 に進む。
- merge の前に Claude が独立に検証し、本人の承認を得てから main に統合する。
- `ROADMAP.md` の「現在地」と「完了までの計画」を、段の着手・完了と同じ commit で更新する。
