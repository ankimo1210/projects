# D3：定性節と章単位の受入を軽く進める案

- 日付：2026-09-27。提案段階。台帳schema・検査・accepted件数は変更していない。
- 原則：原典要求の量に合わせて作業を減らし、必要な表示確認と根拠は残す。
- 現行契約：[SECTION_LEDGER_GUIDE](../../SECTION_LEDGER_GUIDE.md)。

## 1. 現行規約で可能な案

定性節も `explanation` と `rendered` は必須。`implementation`、`independent_validation`、
`visualization` は不要な理由を要求ごとに記せば `not_applicable` にできる。
したがって「図を新設しない」は可能だが、「配布画面を確認しない」は現行規約のままではできない。
ROADMAPの当初案にある後者を自動採用しない。

| 類型 | 最小の根拠 | 省けるもの |
|---|---|---|
| 制度・用語・運用の純定性 | 原典ページ、要求一覧、説明位置、Book/portalの読込・文章・数式/リンク確認 | 計算コード・数値試験・新規グラフ。各N/Aの理由を記載 |
| 歴史的統計の引用 | 年・母集団・単位・原典の位置を確認。最新値と区別 | 引用値を計算機で再現するだけのテスト |
| 小さな算術例を含む節 | 独立手計算、丸め規約、入力・出力を追加 | 問いに寄与しない図。計算要求全体のN/A化は不可 |
| モデルの説明と数値手順が混在 | 定性要求と計算要求を分け、それぞれ必要な根拠 | 節の分類だけを理由に計算要求を除外しない |

監査の「定性63節」は2026-09-14時点の目安。今回の要求草稿で再分類し、63件を一律に軽量受入へ送らない。
Ch36の企業価値MCなど、説明調でも数値手順が本体の節は特に注意する。

## 2. 章単位でまとめる範囲

1. 同じnotebook/教材を使う複数節の原典要求を先に確定する。節ID・要求IDは別々に保つ。
2. 共通のbuildと画面巡回を1回行い、各節の到達anchor・確認結果を一つのmanifest内で対応付ける。
3. 章の先頭1枚の画像だけで全節を確認済みにしない。表示崩れ・数式・リンク・表は対象位置で確認する。
4. 同じ素材の画像はD1の内容hashで共有し、数値・説明・画面の根拠IDから参照する。
5. 失敗した要求/節はpendingのまま残す。章全体を一括でacceptedにするために失敗を隠さない。

仕様変更のない範囲でも、新しい記録の読込み互換性はD1-preflightで確認する。
共通素材の変更時は依存する節を再確認し、無関係な節の証跡を作り直す条件はD1の依存hashで決める。

## 3. 試行と判断材料

最初は純定性2節・算術混在1節の小さな組で試す。所要時間、画像数/byte数、要求数、
レビューで見つかった見落とし、再検査の範囲を記録する。
速度目標のために要求を減らさず、従来方式と同じ論点を確認できるかを比較する。
この試行も本編の該当章の順序で行い、準備段階では受入しない。

**提案する選択：** 現行の5観点を維持し、不要な3観点のN/A理由と章単位の実行共有で軽くする。
もし `rendered` 自体を省く方針へ変えるなら、別途D3の承認、schema/検査/受入定義の変更が必要。
研究の置き場と再開条件に対する今回の回答は、その承認を含まない。

全体日程をこの提案だけで短縮確定とはしない。pilotの結果からP段階ごとの見積りを更新する。
