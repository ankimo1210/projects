# 節受入・再検査の証跡方針（D1）

更新日: 2026-09-28
状態: **M15（§27.6）で本運用を開始。**

関連: [ROADMAP](../ROADMAP.md)、[節別台帳規約](SECTION_LEDGER_GUIDE.md)、
[ワークスペースの保管先](../../docs/decisions/0004-artifact-storage-and-evidence.md)。

## 決定と対象

D1 は画像の重複保存と再撮影の範囲を変える。数値検証・意味の照合・受入条件・release gate は維持する。
新規節の受入には引き続き explanation / implementation / independent validation /
visualization / rendered の証跡を揃える。N/A は台帳規約に従って理由を付け、
explanation と rendered は省略しない。定性節の受入を軽くする D3 は別判断のまま。

M15 の前提として、新形式の検証器と保管庫からの復元を
[§27.3 の実証](validation/d1-preflight/README.md)で確認した。
既存形式の台帳・画像・JSON は変更せず、新形式を追加で検証する。

## 画像の取得・再利用

| 節への影響 | 実施する検査 | 保存する証跡 |
|---|---|---|
| 新規受入・説明や計算や描画に変更 | 数値・notebook・Book/portal の現行検査。既定の両画面幅と操作を検証 | 新しい受入画像、検証結果、入力・ソース・出力の指紋 |
| 受入済みで依存が不変と証明できる | 現行 run のソース・artifact 整合検査、数値・意味・release 検査 | 現行 run の要約と、再利用する基準証跡への参照。画像を複製しない |
| 共有テンプレート・CSS・JS・フォント・描画環境が変更 | 影響する受入済み全節を再描画・画面検証 | 同一バイトの画像は保管庫で共有。差分がある画像は新規保存 |
| 依存関係や影響が不明 | 影響ありとして再描画・画面検証 | 検査結果と新しい基準証跡 |

「無関係な節を notebook に追加しただけ」で過去全節の画像を撮り直さずに済むよう、
節の依存指紋を導入する。構成要素は、対象セルのソースと出力・関連 hullkit 関数とデータ・
図の仕様・本文/DOM 構造・共有描画資産・実行/描画バージョン・viewport・locale 等。
正規化してよい可変部分（日時など）は検証規約に列挙し、数値・本文・式・図を除外しない。
依存マップの網羅性が保証できない段階では、ファイル全体のハッシュを保守的な代替として使う。

Book と portal の基準証跡は別に持つ。依存ハッシュが同じでも、必要な基準画像が消失・破損していれば
再利用を PASS にしない。目視や相互作用確認が必要な変更は既存の検査を実施する。
画像の同一性だけで数値や解説の正しさを認定しない。

## 記録と保存

- Git: 現行 run の結果、対象 commit、節ごとの判定（新規検証/基準再利用）、依存指紋、
  検証器と環境の版、基準証跡の commit/run ID、artifact の SHA-256・サイズ・論理参照を記録する。
- 画像: 受入時の最小証跡は当面 Git に保持する。新しい再検査画像は ADR 0004 の不変保管庫に保存し、
  同一内容を重複保存しない。ハッシュだけ残して実体を捨てる運用は採用しない。
- 基準再利用: 元画像への直接参照と検証器の記録を残す。参照の連鎖や循環で元画像を見失わないようにする。
- 履歴: 過去の受入 JSON やスクリーンショットを新しい結果で上書きしない。
  新しい run が過去 run を参照する。既存 source/artifact ハッシュの意味を一括で書き換えない。
- 障害: 必要 blob の欠損・ハッシュ不一致・復元失敗は検証失敗。第2コピーからの復元にも同じ照合を行う。
  オフラインで検査を省略した場合は未検証を明記し、accepted や release PASS を付けない。

## M15 より前の D1-preflight

| 順 | 実装・検証 | 完了条件 |
|---|---|---|
| 1 | 依存指紋、基準参照、不変 blob の schema と保存・復元器を追加 | path traversal、欠損、破損、既存ファイル衝突を拒否。2コピーから復元したバイト列が一致 |
| 2 | 台帳検証器と再検査スクリプトを拡張 | 現行のファイル参照をそのまま検証でき、新形式でも同等の PASS/source/artifact 検査を行う |
| 3 | 受入済みの1節で両経路を比較 | 全再描画と基準再利用の対象範囲・結果が一致。新規 run から基準画像を復元して閲覧できる |
| 4 | 変更の伝播をテスト | 無関係なセル追加は再利用可、関連セル・共有 CSS・描画器の変更と未知の依存は再利用不可 |
| 5 | 小群の保管と既存 gate を検証 | 2コピーのハッシュ・復元、台帳の artifact 確認、当該節の数値・notebook・Book/portal 検査が通る |

全段階の結果は[実証記録](validation/d1-preflight/README.md)にまとめた。
台帳の受入件数はこの方針決定では変わらない。

## M15 での本運用（2026-09-28）

M15 は既受入14節を D1 の driver（`scripts/d1_preflight_compare.py --records-dir docs/validation/d1-recheck`）で再検査した。記録は `docs/validation/d1-recheck/section-*/`、画像は保管庫。

- vol10 の9節は M15 途中の再描画を基準に**再利用**（新規保存0バイト）。vol06 の5節は §12 の追加で notebook と Book/portal が変わり**再描画**（2,338,282バイト）。
- 依存指紋の `report/report_builder/*.py` は全節共通の入力。新しい節の図を登録すると全節の記録が古くなるので、節の追加ごとに全節の記録を作り直す。依存が変わっていなければ再利用で済み、画像は増えない。
- 描画環境の Playwright の版は指紋に入る。標準は **Playwright 1.56.0 と Chromium 145.0.7632.6（ms-playwright chromium-1208）**。版が変わると再利用できず再描画になる（§27.3 は D1-preflight の 1.62.1 から 1.56.0 に替わって再描画、16画像は基準とバイト一致）。
- 撮影は常にバイト一致するとは限らない（modebar や凡例の数画素）。再描画の判定は検証器の数値・配置検査で行い、バイト一致は要求しない。
- `verify_section_ledger.py --check-artifacts` は現在の環境で指紋を計算し直すので、保管庫の2変数に加えて `PLAYWRIGHT_MODULE` と `CHROMIUM_BIN` も記録時と同じものを渡す。
