# レビュー対応（2026-08-17）

[REVIEW-2026-08-17.md](REVIEW-2026-08-17.md) の指摘 F-01〜F-11 への対応記録。

## 要旨

- **9件を修正、2件を部分対応**（F-08 と F-04 は仕組みを入れたが、全面的な不確実性
  分析と弾力性の実証は残る）。P2 の3件は未着手で、下の「残っている限界」に置いた。
- **結論は変わらず、むしろ強くなった。** 右上（AI解放）は AIラリー開始以降ユニバースに
  負けている。修正前は +89.6% 対 +120.2%（差 −30.6pp）、**修正後は +56.3% 対 +107.9%
  （差 −51.6pp）**。差が広がったのは象限境界の統一（右上が 320 → 645社）と as-of の
  修正（月中値を月末値として扱っていた）の両方が効いている。
- **感応度を6通り＋境界3通りで振っても、右上がユニバースに負ける向きは全通りで成立**
  （下表）。一方で残り3象限の序列は分割方法で入れ替わるので、語れるのは右上だけ。
- 数字の面でいちばん大きく動いたのは象限の企業件数と株価の as-of。P/L の水準は
  福利厚生係数の修正で約3%下がった（順位は不変）。

## 感応度（`tools/sensitivity_grid.py`）

| 設定 | AI解放 業種数 | AI解放 企業数 | 右上 等ウェイト | ユニバース |
|---|---:|---:|---:|---:|
| base（実現率0.30） | 5 | 645 | +56.3% | +107.9% |
| 実現率 0.15 | 5 | 645 | +56.3% | +107.9% |
| 実現率 0.50 | 5 | 645 | +56.3% | +107.9% |
| 規制ドラッグ = 0 | 7 | 653 | +56.9% | +107.9% |
| 境界 = 絶対50 | 1 | 50 | +75.8% | +107.9% |
| 企業の傾き = 0点 | 5 | 645 | +56.3% | +107.9% |
| 境界 = 33業種の上位1/3 | 2 | 193 | +63.5% | +107.9% |

読み方:

- **実現率は象限を動かさない。** 既定設定では33業種すべてで「AIが空ける労働 > 欠員率」
  なので、実現率を 0.15〜0.50 で振っても `min()` の上限は欠員率側に留まる。実現率が
  効くのは P/L の水準だけ。
- **規制ドラッグを0にすると2業種増える**（海運業・空運業が人手依存から移り、機械と
  その他製品が AI増益から低感応へ）。「規制ドラッグは順位を入れ替えない」という前版の
  記述は強すぎたので直した。
- **絶対50 は厳しすぎる。** min-max で作った相対スコア上の固定値なので、経済的な絶対
  基準ではない（レビューの指摘どおり）。右上が1業種50社に絞られる。
- **右上がユニバースに負ける向きは全通りで成立**（+56.3% 〜 +75.8% 対 +107.9%）。

境界の定義を4通りに振ると（すべて as-of 2026-07月末、等ウェイト）:

| 境界 | AI解放 | AI増益 | 人手依存 | 低感応 |
|---|---:|---:|---:|---:|
| 企業1,642社の中央値（**修正前**） | 315社 **+82.9%** | 458社 +134.8% | 366社 +96.8% | 472社 +107.3% |
| 33業種の中央値（**現行**） | 634社 **+56.3%** | 594社 +148.2% | 215社 +154.0% | 168社 +101.8% |
| 絶対しきい値 50 | 50社 **+75.8%** | 572社 +108.1% | 283社 +68.3% | 706社 +126.0% |
| 33業種の上位1/3 | 189社 **+63.5%** | 584社 +129.9% | 319社 +74.5% | 519社 +120.0% |

1行目は**修正前の境界**でも右上が負けていることを示している。つまり結論は境界の直し方に
依存していない。一方で 人手依存 は +68.3% ↔ +154.0%、低感応 は +101.8% ↔ +126.0% と振れるので、
**象限別の順位を語れるのは右上についてだけ**である。

### P/L の水準は仮定の置き方でゼロを割る

`tempered_recovery`（弾力性0.7 × 需要回収0.6 × 自社残存0.7、導入費 売上比0.2%）で
確認済み企業の押上げ幅の中央値は **+0.435pp → −0.072pp**。押上げ幅はもともと
売上の0.4%程度の話なので、**売上比0.2%の導入コストと同じ桁**である。
既定値（中立）の数字を「期待利益」として読んではいけない、という F-01/F-04 の指摘は
この一点でも正しい。

## 再現手順

```bash
cd ~/projects && uv sync --all-packages

# 生ファイルの突合（_data/sources/ を持っている場合）
uv run --no-sync python labor_ai_quadrant/tools/source_manifest.py --check

# 参照テーブルの再生成 → 再スコア → 感応度 → 株価
uv run --no-sync python labor_ai_quadrant/tools/build_reference.py
uv run --no-sync python labor_ai_quadrant/tools/rescore_topix.py
uv run --no-sync python labor_ai_quadrant/tools/sensitivity_grid.py
uv run --no-sync python labor_ai_quadrant/tools/quadrant_performance.py

# テスト（120件）。--noconftest は付けない
uv run --no-sync pytest labor_ai_quadrant/tests -q
```

`--noconftest` を付けるとルート `conftest.py` の `import labor_ai_quadrant` が走らず、
同名ディレクトリが namespace package として先に解決されて6モジュールが
`ModuleNotFoundError` になる。この import はワークスペース共通の対策
（`docs/decisions/0002-workspace-green-and-declared-dependencies.md`）で、
`quantkit` / `gto` / `optimal_execution` / `rough_volatility` も同じ扱い。

## 残っている限界

レビューの P2 と、対応が部分に留まったもの。

- **F-04 の実証。** 弾力性・需要回収率・自社残存率は Config に出したが、値そのものの
  根拠は無い（`tempered_recovery` の 0.7/0.6/0.7 は例示）。欠員率と売上の関係を
  業種パネルで推定するのが本筋で、それはやっていない。
- **F-08 の全面版。** 象限所属確率の表示、ISCO 対応と4桁単純平均のブートストラップ、
  親会社閾値の感応度は未実装。`sensitivity_grid.py` は6設定＋境界3通りまで。
- **バックテストの設計（P2）。** 当時点の構成銘柄ではなく現在の TOPIX を遡って当てて
  いるので生存バイアスが残る。上場廃止銘柄・sector/factor neutral 版も未実装。
  リバランスもしていない。
- **企業固有の情報が無い（P2）。** J-Quants から企業属性が取れないので `labor_intensity`
  / `knowledge_tilt` は全社 "mid"。企業スコアは実質、業種スコアの転写である
  （だから傾き0のテストが全行一致で通る）。企業別のAI導入度・職種構成・求人は未取得。
- **CI が無い。** テストコマンドは通るが、ワークスペースの `make test` の `testpaths` に
  `labor_ai_quadrant/tests` を登録しただけで、参照再生成と manifest 突合は CI で
  回っていない。
