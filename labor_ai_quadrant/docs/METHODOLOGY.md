# METHODOLOGY

2軸の定義、データの出所、そして **何を主張していないか**。

---

## 1. なぜ2軸なのか

「人手不足だからAIが効く」という主張は、そのままでは検証できない。分解すると2つの
独立な問いになる。

1. その企業の労働は、いま本当に採れていないのか（＝制約になっているか）
2. その労働は、いまのAIで代替できる種類の労働なのか

この2つは独立に測れて、しかも **日本では負の相関を持ちやすい**。人手不足が最も深刻な
職業（建設・採掘、介護、自動車運転、保安）は身体労働であり、生成AIの射程外にある。
一方で生成AIの射程内にある事務職は、有効求人倍率で見れば長く1倍を下回っている。

したがって右上（両方が高い）は狭く、そこに入ることが情報になる。両者を掛け合わせずに
「AI関連銘柄」と一括りにすると、この分離が消える。

---

## 2. X軸 — 人手不足の深刻度

### 指標と重み

| 指標 | 重み | 出典 | 全産業アンカー |
|---|---|---|---|
| `vacancy_rate_pct` 欠員率 | 0.30 | 厚生労働省「雇用動向調査」産業別（未充足求人数 ÷ 常用労働者数） | 約2.9%（2024年6月末） |
| `job_openings_ratio` 有効求人倍率 | 0.25 | 厚生労働省「一般職業紹介状況」職業別 | 約1.2倍 |
| `tdb_shortage_pct` 正社員不足割合 | 0.25 | 帝国データバンク「人手不足に対する企業の動向調査」 | 50.6%（2026年4月） |
| `age55_share_pct` 55歳以上就業者比率 | 0.10 | 総務省「労働力調査」産業別 | — |
| `separation_rate_pct` 離職率 | 0.05 | 厚生労働省「雇用動向調査」産業別 | — |
| `overtime_hours_month` 所定外労働時間 | 0.05 | 厚生労働省「毎月勤労統計調査」産業別 | — |

重み付けの考え方: 上位2つは「いまこの瞬間に採れていない」ことの直接的な測度。TDB調査は
経営者の主観だが、実務で最も参照され速報性がある。残り3つは将来圧力（高齢化）と不足の
帰結（離職・残業）であり、二重計上を避けるため軽く置く。

### 計算

```
z_i     = 業種横断の z-score（各指標）を ±2.5 でクリップ
composite = Σ_i weight_i × z_i
shortage_score = composite を 33業種内で min-max して 0-100
```

z値を ±2.5 でクリップするのは、建設業の有効求人倍率（5倍超）のような単一の極端値が
合成スコア全体を支配するのを防ぐため。

### 既知の限界

- **産業分類の不一致**: 政府統計は日本標準産業分類（JSIC）、東証は33業種。一対一対応は
  しない。`jsic` 列に対応元を明示したうえで analyst が按分している。個々のセルは
  「公表値そのもの」ではなく「公表値に整合するよう配賦した参照値」。
- **33業種「サービス業」の粒度**: 人材派遣・警備・介護・外食・広告・レジャーが同居する
  最大の雑多カテゴリ。人手不足スコアは高く出るが、内訳の分散も最大。企業レベルでは
  `labor_intensity` / `knowledge_tilt` でしか補正していない。
- **上場企業 ≠ 産業全体**: 統計は産業全体（中小企業を含む）で取られている。上場企業は
  賃金・採用力で優位にあり、同じ業種でも不足感は相対的に軽い可能性が高い。
  この軸は「その業種で戦うことの難しさ」であって「その企業が採れていない度合い」ではない。

## 3. Y軸 — AI代替可能性

### 構造

ボトムアップで計算する。

```
ポテンシャル[職業] = llm_potential × (1 - w) + phys_potential × w        # w = robotics_weight
sector_ai_share    = Σ_職業 ( 構成比[業種][職業] × ポテンシャル[職業] ) × (1 - regulation_drag[業種])
ai_score           = sector_ai_share を 33業種内で min-max して 0-100
```

`sector_ai_share`（`ai_substitutable_share_pct`）は「その業種の労働のうちAIで代替しうる
割合(%)」という解釈可能な水準値。`ai_score` はそれを相対化した象限マップ用の指標。
**P/L への換算には必ず前者を使う**（相対値を金額に掛けると桁が壊れる）。

### 職業分類

日本標準職業分類の大分類（11区分）をベースに、AI感応度の分散が大きい「専門的・技術的
職業従事者」だけを5つに細分した **15区分**。情報処理技術者（LLM感応度が最大）と保健医療
従事者（規制と身体性で最小に近い）を同じ箱に入れると軸が意味を失うため。

### 2成分に分ける理由

`llm_potential` と `phys_potential` を分離しているのは、「AI」という言葉が2つの別の技術を
指しているから。

- **生成AI(LLM)**: 事務・審査・与信・設計・コーディングに効く。実装は速く、資本支出は小さい
- **ロボティクス・自動運転**: 倉庫内搬送・生産工程・運転に効く。実装は遅く、資本支出は大きい

混ぜたまま1つの数字にすると、陸運業の評価が「自動運転がいつ来るか」の仮定に丸ごと
依存してしまい、それが見えなくなる。分けたうえで `robotics_weight` で振ることで、
その依存を明示的に扱える。

| シナリオ | robotics_weight | 意味 |
|---|---|---|
| `llm_only` | 0.00 | いま確実に効くものだけ。保守的 |
| `base` | 0.35 | 既定。LLMが主、物理自動化は一部実装済み |
| `llm_plus_robotics` | 0.60 | 自動運転・倉庫自動化が本格化する前提 |

### 規制ドラッグ

同じ職種構成でも、監督官庁の検証要求が重い業種はAI実装が遅れる。医薬品・電力・航空
（0.18）、金融（0.15）、陸運（0.15）などに 0.00-0.20 の範囲で掛け目を置いている。
これは analyst 設定値であり、実装遅延の観察に基づく粗い調整。

### 既知の限界

- **`llm_potential` / `phys_potential` は analyst 設定値**。Eloundou et al. (2023)
  "GPTs are GPTs"（事務・専門職が高く身体労働が低い）と Felten, Raj & Seamans (2021)
  の AI Occupational Exposure を方向性のアンカーにしているが、
  米国SOCから日本標準職業分類への正式なクロスウォークは適用していない。
  **個々の数値の絶対精度は主張しない。職業間の順序に意味がある。**
- **代替可能性 ≠ 実装**。この軸は技術的な代替可能性の上限であって、経営が実際に
  実装するかは別問題。そこは `realization_rate` で明示的に割り引く。
- **AIが需要側に効くケースを織り込んでいない**。情報・通信業のSIerは、AIで
  「自社の人月が減る」と同時に「AI導入案件で売上が増える」。この枠組みは前者
  （コスト・供給制約）だけを測る。後者はここには入っていない。
- **構成比は analyst 読み替え**。国勢調査の産業×職業クロス集計を東証33業種へ
  対応付けたもので、行和は正規化してから使う。

## 4. 4象限の分割

既定は **中央値分割**（`threshold_method="median"`）。ユニバース内の相対評価であり、
定義上おおむね各象限に1/4ずつ入る。しきい値ちょうどの値は **低い側** に数える
（右上が同値で膨らまないように）。

絶対評価をしたい場合は `threshold_method="fixed"`（既定しきい値 50）に切り替える。

**脱出ポテンシャル** は2軸の **幾何平均**:

```
escape_potential = √(shortage_score × ai_score)
```

算術平均にすると建設業（100, 3）のような「人手不足は極端だがAIでは解けない」ケースが
上位に来てしまい、枠組みの意味が失われる。幾何平均は片方が0なら0になる。

## 5. 企業レベルへの展開

象限上の位置は業種でほぼ決まる。企業固有の差分は2属性のみ:

| 属性 | 動かす軸 | 意味 |
|---|---|---|
| `labor_intensity` | X（人手不足） | 労働集約度。high = 人月・人海戦術型で従業員1人当たり売上が小さい |
| `knowledge_tilt` | Y（AI代替） | ホワイトカラー比率。high = LLM が効く面積が大きい |

low/mid/high の3値で、`tilt_points`（既定 8.0）の幅を動かす。**正規化前の生値に適用**し、
そのうえで企業ユニバース内で 0-100 に再正規化する。正規化後に足す実装だと、首位業種の
企業が全部 100 に張り付いて within-sector の差が消える（`test_tilts_do_not_collapse_onto_the_ceiling`）。

3値 × 3値なので、1業種あたり最大9通りの位置しか取れない。**同順位が多く出るのは仕様**で、
それを解くのが次節の財務レイヤ。

## 6. P/L への換算

```
AI代替可能な人件費 = 人件費 × (ai_substitutable_share_pct / 100)
期待削減額         = AI代替可能な人件費 × realization_rate
営業利益押上げ余地 = 期待削減額 ÷ 営業利益 × 100 [%]
```

`realization_rate`（既定 0.30）は「技術的に代替可能」と「実際に人件費が減る／増員を
回避できる」のギャップ。0.15（保守）〜0.50（積極）で振れる。

営業利益が 0 以下の企業では押上げ余地は定義できないため **NaN** を返す（巨大な正の値を
返さない）。財務データが無い銘柄も NaN で、部分カバレッジは想定内。

### この計算が言っていないこと

- 削減された人件費が **そのまま営業利益に落ちる** という前提を置いている。実際には
  価格競争を通じて顧客に移転する部分がある。特に労働集約型の受託業（SI・人材・警備）
  では、AIによる省力化が単価下落として出る可能性が高い。
- AI導入コスト（ライセンス・実装・再教育）を引いていない。
- 日本の雇用慣行上、人員削減は短期には進まない。効くのは主に **増員回避** の形。

## 7. データの更新

参照テーブルは `src/labor_ai_quadrant/reference/*.toml`。すべて出典コメントと `vintage`
付き。更新は該当 TOML の差し替えで完結し、コードは触らない。

| ファイル | 更新元 | 頻度 |
|---|---|---|
| `sector_labor_shortage.toml` | e-Stat（雇用動向調査・毎月勤労統計・労働力調査）、一般職業紹介状況、TDB調査 | 四半期 |
| `occupation_ai_exposure.toml` | 文献の更新時のみ | 年次 |
| `sector_occupation_mix.toml` | 国勢調査（5年ごと） | 5年 |
| `universe_jp.toml` | J-Quants `/v2/equities/master`（`verify-universe` で差分検出。旧 `/v1/listed/info` は 2026-08 時点で廃止済み） | 年1回（10月の定期入替後） |

`load_reference()` は読み込み時に構造を検証し、壊れていれば具体的なメッセージで
`ValueError` を投げる。手編集される表なので、静かに間違った値が通るより落ちるほうがよい。

## 8. この枠組みが答えない問い

- **バリュエーション**。右上に入ることと、それが株価に織り込まれていないことは別。
- **競争優位**。同じ業種の中で誰がAI実装に成功するかは、この2軸の外側にある。
- **需要側の効果**。AIで売上が伸びる企業（SIer、半導体、電力）はここでは評価されない。
- **タイミング**。「いつ効くか」は `realization_rate` と `robotics_weight` に丸め込まれている。

これは制約に対する **感応度の地図** であって、投資判断そのものではない。
