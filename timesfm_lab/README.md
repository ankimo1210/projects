# timesfm_lab — TimesFM 3.0 の反証ベンチ

Google Research の時系列基盤モデル **TimesFM 3.0** をゼロショットで動かし、
意図的に強くした 7 つの古典ベースラインとローリング原点バックテストで
比較する。目的は「基盤モデルが速いか」ではなく、**どこまでが本物の
優位で、どこからが測り方の産物か**を切り分けること。

そのために、公開ベンチだけでなく **絶対に学習され得ないデータ**を 3 種類
用意している — 既知の生成過程から作った合成系列（理論限界が計算できる）、
2026 年の市場データ、そして**2026 年の英国高速道路センサー計数**（学習済みの
`traffic_hourly` と領域・頻度・季節構造が揃った領域対照）。

レポート（HTML / Artifact）: https://claude.ai/code/artifact/db4ac429-0c3f-4725-ba99-3eff5d0d741d
ディスク上の同内容: `reports/report.html`

> **結論は二度訂正している。**初版（2026-09-06）は「汚染仮説は棄却された」と
> 書き、改訂 1 はそれを撤回して「層をまたぐ比較はむしろ汚染を示唆する」と
> 書いた。改訂 2（2026-09-07）で、領域対照によりその示唆も落ちた。
> 詳細は「学習データ汚染について」。

## 結論（2026-09-07 改訂 2、seed=0）

24 データセット・3,130 窓を、**TimesFM の学習コーパスとの関係で 5 層**に
分けて測る（`src/timesfm_lab/tiers.py`）。

| 問い | 答え | 根拠 |
|---|---|---|
| 単体の古典手法に勝つか | **勝つ** | 7 手法すべてに勝率 72〜80%、p < 1e−4。最良の単体（Theta 1.596）を 22.5% 上回る |
| 窓ごと最良の選択に勝つか | **負ける** | オラクル MASE 1.092 対 1.250 |
| そのオラクルは到達可能か | **できない** | 実装可能な選択器は 1.456 止まり。的中率 30.6%（偶然 14.3%） |
| 優位は汚染で説明できるか | **説明できない** | 同領域で未学習の交通 2026 が +54.9%、学習済みの traffic_hourly が +41.0% |
| どこで勝つのか | **領域で決まる** | 多数センサーの時間足で +41〜55%、市場で +8.9% |
| 共変量は効くか | **効かない** | 3 設定 6 検定すべて p ≥ 0.33。真のドライバを渡しても余地の 2.7% しか埋まらない |
| 合成データで古典手法に勝てないのは | **テストの問題** | 最初の 8 過程中 5 つは改善の余地が 2.6% 以下だった |
| 不確実性は信用できるか | **古典手法よりは** | 名目からの平均乖離 0.042 で全モデル 1 位。ただし 80% 区間の被覆 0.785 |

**sMAPE では季節ナイーブが 1 位**になる（36.1 対 38.8）— solar と weather の
ゼロ近傍で分母が潰れるためで、同じ予測値から指標の選択だけで別の結論が作れる。

## 学習データ汚染について（二度の訂正の記録）

TimesFM 3.0 のモデルカードは学習源に `GiftEvalPretrain` を挙げている。その
中身を開いたところ、**Monash の `traffic_hourly` と `weather` が入っており、
値がバイト単位で一致した**（各 25 系列を `rtol=1e-4` で照合、全一致）。
コーパス側は末尾のテスト区間だけを削った完全なコピーで、traffic は 168 点
（7 日）、weather は 30 点短い。この事実は三つの版を通じて変わらない。

**初版の誤り。** 窓を「予測対象がコーパス内 / 外」で二分した検定
（p = 1.00 / 0.54）から汚染仮説を「棄却」した。検定自体は正しく計算されて
いるが、**文脈側の被覆が traffic 96.5%・weather 100.0%** で、どちらの群も
条件付けに使う窓は丸ごと学習済みだった。あの検定が検出できるのは「答えその
ものの記憶」だけで、「系列に対する馴染み」には構造的に盲目である。

**改訂 1 の誤り。** 未学習データ（合成・金融 2026）を足すと層をまたいで
勾配が出た（学習済み +36.3% 対 未学習 +7〜9%、対 実装可能な選択器）ので、
これを「汚染が効いている示唆」と書いた。同時に「層は領域と交絡している」
とも書いたが、その交絡を切らずに示唆を主張したのが行き過ぎだった。

**改訂 2：領域対照。** 交絡を切るために、`traffic_hourly` と**同じ形**の
系列で**カットオフの反対側**にあるものを作った — National Highways の
WebTRIS API から取った、2026 年 1〜6 月の英国高速道路の時間別計数
（`traffic_uk.py`）。時間足・多数センサー・日次 + 週次周期という構造が揃い、
日付が未学習を保証する。

| | コーパスとの関係 | 系列 | 窓 | TimesFM | 選択器 | 改善 | 勝率 |
|---|---|---|---|---|---|---|---|
| `traffic_hourly` (Monash) | **学習済み**（実データ照合） | 40 | 200 | 0.641 | 1.085 | +41.0% | 83.0% |
| `traffic_uk_2026` (WebTRIS) | 2026 年・学習不能 | 28 | 140 | 0.552 | 1.224 | **+54.9%** | **97.9%** |

**未学習の側の方が優位が大きい。** 記憶が優位の source なら未学習側で縮む
はずだった。層の平均も勾配にならない — 学習済み +36.3% / 一覧に無い +7.4% /
合成 +10.0% / 金融 2026 +8.9% / **交通 2026 +54.9%**。traffic と weather が
突出していた理由は「学習済みだから」ではなく、多数センサーの時間足という形が
基盤モデルに最も有利で古典手法に最も不利だから、と読むほうが整合する。

**なお言えないこと。** 対照は交通 1 領域ぶんで、`weather` に対応する対照は
無い。対照側にも別の交絡がある（英国 vs 米国、車両台数 vs 車線占有率、
文脈長 1,024 vs 512）。「同じ領域」は厳密には「同じ形の系列」である。

残り 5 系統（electricity・ETTh1/h2・solar・河川流量）は GIFT-Eval のテスト側
にあるため GiftEvalPretrain から除外されている。fev-bench のタスク一覧にも
Monash の traffic / weather は無いので、モデルカードの「fev-bench と重なる
ものを除外」ではこの 2 つは落ちない。

## 合成データ：勝てなかったのか、勝ちようが無かったのか

真の生成過程が既知なので、条件付き分布から**到達可能な下限**が出る。点予測の
下限は絶対誤差を最小化する**条件付き中央値**（平均ではない — 間欠需要のように
ゼロに質量が集中する分布で両者は大きく食い違い、平均を使うと「最適解」が
TimesFM に 43% 負けるという不可能な結果が出る）。

下限が計算できるなら、**改善の余地**も計算できる：最良の古典手法の誤差のうち、
完璧な予測器なら消せる分の割合。最初の 8 過程では TimesFM がほとんど勝てず、
これを「基盤モデルの限界」と読みかけたが、余地を見ると**5 つは 2.6% 以下**
だった。誰が来ても勝てない問題を出していたことになる。

そこで古典手法が構造的に表現できない 5 過程を足した（閾値 AR・位相ドリフト・
振幅変調・長期記憶・未観測ドライバ）。余地が生まれた場所では取りに来る。

| 過程 | 理論限界 | 最良古典手法 | TimesFM | 余地 | 回収 |
|---|---|---|---|---|---|
| 決定論的カオス | 0.000 | 0.569 | 0.565 | 100.0% | **0.8%** |
| 位相ドリフト | 0.222 | 0.684 | 0.428 | 67.5% | **55.3%** |
| 振幅変調 | 0.565 | 1.164 | 0.655 | 51.5% | **84.9%** |
| 未観測ドライバ | 2.322 | 3.795 | 3.800 | 38.8% | **−0.3%** |
| 間欠需要 | 0.533 | 0.811 | 0.537 | 34.3% | **98.7%** |
| 水準ジャンプ | 1.568 | 1.754 | 1.757 | 10.6% | −1.1% |
| （残り 7 過程） | | | | ≤ 2.9% | 読む価値なし |

余地 3% 未満の行の回収率は読まないほうがよい（分母が小さいほど比が暴れる。
`syn_trend_seasonal` の −77% は MASE 0.685 対 0.695 の話）。

取れなかった 3 つが別々のことを示す。**決定論的カオス**は理論限界が誤差
ちょうど 0 なのに誰も再帰を同定していない。**未観測ドライバ**は目標系列だけ
からは原理的に情報が足りない（→ 共変量実験）。**水準ジャンプ**はレジーム
切替を検出していない。

## 共変量：目玉機能が、渡しても動かない

TimesFM 3.0 の目玉は共変量サポート。**同じモデル・同じ窓を 2 回採点**して
切り出した（`covariates.py` / `scripts/run_covariates.py`）。

| 設定 | チャネル | 窓 | MASE 単変量 → 共変量あり | 変化 | p |
|---|---|---|---|---|---|
| 合成・真の潜在ドライバ | 1 | 120 | 3.800 → 3.699 | −2.7% | 0.52 |
| ETTh1（6 負荷 → 油温） | 6 | 12 | 0.747 → 0.746 | −0.1% | 0.73 |
| 金融レンジボラ + 出来高 | 1 | 108 | 0.712 → 0.718 | +0.9% | 0.73 |

6 検定すべて有意でない。**自分で作った過程で、共変量が信号の全てだと
分かっているケース**（余地 38.8%）ですら 2.7% しか埋まらない。

「効かない」を報告する前に経路を確かめてある。`y_t = u_{t−48}` という共変量が
予測区間を完全に決める人工ケースでは **MAE 1.567 → 0.693（−56%）**と大きく
改善し、長さの合わない共変量は例外で弾かれる。null は本物である。

## セットアップ

```bash
# ワークスペースルートから（uv はルートで実行する。member 内で叩くと .venv が増える）
uv sync --all-packages

cd timesfm_lab
./scripts/fetch_data.sh                              # 公開データ約 440MB を _data/ へ
uv run --no-sync python scripts/fetch_finance.py     # yfinance 日次 OHLCV 18銘柄
uv run --no-sync python scripts/fetch_traffic_uk.py  # WebTRIS 40地点・2026年1〜6月
uv run --no-sync python scripts/build_contamination_index.py   # GiftEvalPretrain 照合（約 230MB）
uv run --no-sync python scripts/run_bench.py         # 本走。RTX 5080 で約 640 秒
uv run --no-sync python scripts/run_covariates.py    # 共変量アブレーション
uv run --no-sync python scripts/build_report_data.py # 集計 JSON
uv run --no-sync python scripts/build_report.py      # HTML 2 種を生成
```

初回は HuggingFace から重み（約 800MB）を取りに行く。GPU が無いときは
`--device cpu`。

## 設計上の判断

- **ベースラインは全部確率予測にした。** 季節ナイーブには経験残差ブート
  ストラップの区間を付けてある。基盤モデルの論文が省きがちな、確率予測と
  して本当に手強い相手を用意するため。金融のために **HAR**（Corsi）と
  **EWMA** も足してある。
- **評価窓は重ねない。** 重なると誤差が系列相関して有意差が過大に出る。
- **MASE の分母は文脈側だけから作る。** 検証区間で正規化すると答えが分母
  に漏れる（`metrics.seasonal_scale_mae`）。
- **オラクルは手法ではない。** 窓ごとに全手法の最小を取る操作は、定義上
  どんな単体手法より良くなる。実装可能な選択器（直前の窓の勝者を引き継ぐ）
  と必ず並べて出す（`analysis.selector_table`）。実証もしてある — 既存より
  悪い HAR と EWMA を足すだけでオラクルは −1.4%、選択器は −0.1% しか動かない。
- **PIT は mid-PIT。** solar は 63% が厳密ゼロで、同点を全部ヒットに数えると
  10% 水準の較正が 0.70 という無意味な値になる。
- **理論限界のモンテカルロには対称変量法を使う。** 条件付き期待値がショックの
  線形関数になる過程では、これで下限が厳密になる（4,000 本の素朴な平均では
  ランダムウォークの「最適解」がナイーブ法に負けていた）。
- **合成の種に `hash()` を使わない。** Python の文字列ハッシュはプロセスごとに
  ランダム化されるので、実行のたびに別の系列が生成されて再現性が消える。
  `zlib.crc32` で畳み込む。`test_synthetic.py` が `PYTHONHASHSEED` を変えた
  サブプロセスで実際に検査している。
- **交通 2026 の欠測は補間するが、補間点では採点しない。** WebTRIS は 0.7〜0.9%
  の時間を落とす。1〜6 時間の穴は補間して**印を付け**、印の付いた点を予測対象に
  含む窓は捨てる。それより長い穴は系列を分割する。補間値に対して採点すれば
  測っているのは補間器である。
- **領域対照は独立した層にする。** `traffic_uk_2026` を金融と同じ
  「カットオフ後」層に混ぜると、+54.9% と +8.9% が平均されて対照の意味が
  消える（`tiers.py` の `C_domain_control`）。

## 既知の限界

- **領域対照は交通 1 領域ぶん。** `weather` に対応する対照は無く、対照側にも
  国・計測量・文脈長の違いが残る。
- 共変量は past-only のゼロショットのみ。未来既知の共変量（カレンダー・祝日・
  気温予報）もファインチューニングも試していない。ETTh1 は 12 窓しかない。
- 合成過程は現実より易しい（定常か単純な非定常のみ、構造変化・欠測・複数
  季節性なし）。1 過程 120 窓なので余地の小さい行の回収率は不安定。
- 金融は日次バーのみで、レンジボラは日中データによる実現ボラティリティでは
  ない。銘柄 18、窓は各 6 本。
- ETS は季節周期 48 超で非季節にフォールバックする（solar の 150 窓が該当、
  レポートの表に明記）。AutoARIMA / TBATS / STL は入れていない。
- seed 1 本。系列サンプリングのばらつきは測っていないので、p 値は
  「この系列集合において」と読む。

## ライセンス

コードは Apache-2.0 だが、**TimesFM 3.0 の重みは `timesfm-non-commercial-license-v1.0`**
で商用・本番利用は許諾されていない。商用の可能性を残すなら Apache-2.0 の
ままの 2.5 系（`google/timesfm-2.5-200m-pytorch`）を使うことになる。
