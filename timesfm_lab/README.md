# timesfm_lab — TimesFM 3.0 の反証ベンチ

Google Research の時系列基盤モデル **TimesFM 3.0** をゼロショットで動かし、
意図的に強くした 7 つの古典ベースラインとローリング原点バックテストで
比較する。目的は「基盤モデルが速いか」ではなく、**どこまでが本物の
優位で、どこからが測り方の産物か**を切り分けること。

そのために、公開ベンチだけでなく **絶対に学習され得ないデータ**を 2 種類
用意している — 既知の生成過程から作った合成系列（理論限界が計算できる）と、
2026 年の市場データ（カレンダーが未学習を保証する）。

レポート（HTML / Artifact）: https://claude.ai/code/artifact/db4ac429-0c3f-4725-ba99-3eff5d0d741d
ディスク上の同内容: `reports/report.html`

> **初版（2026-09-06）の結論を 1 点訂正している。**「汚染仮説は棄却された」は
> 過剰な主張だった。詳細は下記「学習データ汚染について」。

## 結論（2026-09-07 改訂、seed=0）

18 データセット・2,362 窓を、**TimesFM の学習コーパスとの関係で 4 層**に
分けて測る（`src/timesfm_lab/tiers.py`）。

| 問い | 答え | 根拠 |
|---|---|---|
| 単体の古典手法に勝つか | **勝つ** | 7 手法すべて、全層で優位。最良の単体（ETS 1.415）を 16% 上回る |
| 窓ごと最良の選択に勝つか | **負ける** | オラクル MASE 0.887 対 1.065 |
| そのオラクルは到達可能か | **できない** | 実装可能な選択器は 1.274 止まり。的中率 29.6%（偶然 14.3%） |
| 優位は汚染で説明できるか | **切り分け未了** | 学習済み +36.3% 対 未学習 +7〜9%（対 実装可能な選択器） |
| 到達可能な精度に届くか | **ほぼ届く** | 合成 8 過程中 6 つで理論限界の +0.4〜4.1% |
| 2026 年の市場で使えるか | **HAR と互角** | 点予測で HAR に有意勝ちは出来高のみ。収益率では負ける |
| 不確実性は信用できるか | **できない** | 80% 区間の被覆 0.792。経験残差付き季節ナイーブの方が較正されている |

**sMAPE では季節ナイーブが 1 位**になる（31.1 対 37.5）— solar と weather の
ゼロ近傍で分母が潰れるためで、同じ予測値から指標の選択だけで別の結論が作れる。

## 学習データ汚染について（初版から訂正）

TimesFM 3.0 のモデルカードは学習源に `GiftEvalPretrain` を挙げている。その
中身を開いたところ、**Monash の `traffic_hourly` と `weather` が入っており、
値がバイト単位で一致した**（各 25 系列を `rtol=1e-4` で照合、全一致）。
コーパス側は末尾のテスト区間だけを削った完全なコピーで、traffic は 168 点
（7 日）、weather は 30 点短い。

**初版はここから汚染仮説を「棄却」したが、それは誤りだった。** 窓を
「予測対象がコーパス内 / 外」で二分した検定（p = 1.00 / 0.54）は正しく
計算されているが、**文脈側の被覆が traffic 96.5%・weather 100.0%** で、
どちらの群も条件付けに使う窓は丸ごと学習済みだった。あの検定が検出できるのは
「答えそのものの記憶」だけで、「系列に対する馴染み」には構造的に盲目である。

そこで**絶対に学習され得ないデータを 2 種類**足した。

- **合成（層 C）** — 既知の生成過程 8 種を種から生成。汚染が原理的に不可能で、
  かつ**到達可能な誤差の下限が計算できる**（`synthetic.py`）。
- **金融（層 C）** — 予測対象がすべて 2026-03-13〜09-07。カードが挙げる
  最も遅いカットオフ（2023-11）より後（`finance.py`）。

層をまたぐと勾配が出る。実装可能な選択器を相手にした改善率は
**学習済み +36.3% / 一覧に無い +7.4% / 合成 +7.2% / 金融2026 +8.9%**。
相手を 4 通り取り替えても層 A が最上位である点は変わらない（層 B と C の
相対順序は入れ替わる）。ただし**層は領域とも交絡している**ので、これは
汚染仮説を裏づける示唆であって証明ではない。最も近い対照は traffic
（862 センサー・時間足・学習済み・+34%）と electricity（321 センサー・
時間足・一覧に無い・−8%）。

残り 5 系統（electricity・ETTh1/h2・solar・河川流量）は GIFT-Eval のテスト側
にあるため GiftEvalPretrain から除外されている。fev-bench のタスク一覧にも
Monash の traffic / weather は無いので、モデルカードの「fev-bench と重なる
ものを除外」ではこの 2 つは落ちない。

## 合成データ：理論限界からの距離

真の生成過程が既知なので、条件付き分布から**到達可能な下限**が出る。点予測の
下限は絶対誤差を最小化する**条件付き中央値**（平均ではない — 間欠需要のように
ゼロに質量が集中する分布で両者は大きく食い違い、平均を使うと「最適解」が
TimesFM に 43% 負けるという不可能な結果が出る）。

| 過程 | 理論限界 | TimesFM の超過 | 最良古典手法の超過 |
|---|---|---|---|
| 間欠需要 | 0.533 | **+0.7%** | +52.1% |
| AR(1) φ=0.85 | 1.794 | +1.3% | +1.6% |
| 周期的な分散 | 0.722 | +2.1% | +2.2% |
| 周期（純粋） | 0.712 | +2.4% | +2.7% |
| ランダムウォーク | 5.135 | +3.4% | −0.4% |
| 周期 + トレンド | 0.672 | +3.4% | +1.9% |
| 水準ジャンプ | 1.568 | **+12.0%** | +11.9% |
| ロジスティック写像 | **0.000** | 誤差 0.565 | 誤差 0.569 |

下限が正の 7 過程のうち 6 つで +0.7〜3.4% に入る。外れる 2 つの外し方が別。
水準ジャンプ（+12.0%）は最良の古典手法も +11.9% なので**問題自体が難しい**。
決定論的カオスは理論限界が誤差ちょうど 0 なのに古典手法との差が 0.7% しかない
—— 到達可能な精度が 100% ある場所で、**誰も 1% も取れていない**。

数値のばらつきに注意。合成の種の与え方を直したとき系列が張り直され、水準
ジャンプの超過は +4.1% から +12.0% に動いた。1 過程あたり 120 窓では、
この程度の変動が残る。

## セットアップ

```bash
# ワークスペースルートから（uv はルートで実行する。member 内で叩くと .venv が増える）
uv sync --all-packages

cd timesfm_lab
./scripts/fetch_data.sh                              # 公開データ約 440MB を _data/ へ
uv run --no-sync python scripts/fetch_finance.py     # yfinance 日次 OHLCV 18銘柄
uv run --no-sync python scripts/build_contamination_index.py   # GiftEvalPretrain 照合（約 230MB）
uv run --no-sync python scripts/run_bench.py         # 本走。RTX 5080 で約 402 秒
uv run --no-sync python scripts/build_report_data.py # 集計 JSON
uv run --no-sync python scripts/build_report.py      # HTML 2 種を生成
```

初回は HuggingFace から重み（約 800MB）を取りに行く。GPU が無いときは
`--device cpu`。

## テスト

```bash
uv run --no-sync pytest timesfm_lab/tests    # リポジトリルートから。76 tests
```

データ未取得だと `test_datasets.py` / `test_contamination.py` / `test_finance.py`

## 設計上の判断

- **ベースラインは全部確率予測にした。** 季節ナイーブには経験残差ブート
  ストラップの区間を付けてある。基盤モデルの論文が省きがちな、確率予測と
  して本当に手強い相手を用意するため。実際これが較正では 1 位になった。
  金融のために **HAR**（Corsi）と **EWMA** も足してある。
- **評価窓は重ねない。** 重なると誤差が系列相関して有意差が過大に出る。
- **MASE の分母は文脈側だけから作る。** 検証区間で正規化すると答えが分母
  に漏れる（`metrics.seasonal_scale_mae`）。
- **オラクルは手法ではない。** 窓ごとに 5 手法の最小を取る操作は、定義上
  どんな単体手法より良くなる。実装可能な選択器（直前の窓の勝者を引き継ぐ）
  と必ず並べて出す（`analysis.selector_table`）。
- **PIT は mid-PIT。** solar は 63% が厳密ゼロで、同点を全部ヒットに数えると
  10% 水準の較正が 0.70 という無意味な値になる。
- **理論限界のモンテカルロには対称変量法を使う。** 条件付き期待値がショックの
  線形関数になる過程では、これで下限が厳密になる（4,000 本の素朴な平均では
  ランダムウォークの「最適解」がナイーブ法に負けていた）。
- **合成の種に `hash()` を使わない。** Python の文字列ハッシュはプロセスごとに
  ランダム化されるので、実行のたびに別の系列が生成されて再現性が消える。
  `zlib.crc32` で畳み込む。`test_synthetic.py` が `PYTHONHASHSEED` を変えた
  サブプロセスで実際に検査している。

## 既知の限界

- 単変量ゼロショットのみ。TimesFM 3.0 の目玉である多変量・共変量サポートも
  ファインチューニングも使っていない。
- **層は領域とも交絡している。** 層 A はセンサーネットワーク、層 C は合成と
  金融。汚染の効果と「領域ごとの伸びしろ」を完全には分離できていない。
- 合成過程は現実より易しい（定常か単純な非定常のみ、構造変化・欠測・複数
  季節性なし）。金融は日次バーのみで、レンジボラは日中データによる実現
  ボラティリティではない。
- ETS は季節周期 48 超で非季節にフォールバックする（solar の 150 窓が該当、
  レポートの表に明記）。AutoARIMA / TBATS / STL は入れていない。
- seed 1 本。系列サンプリングのばらつきは測っていないので、p 値は
  「この系列集合において」と読む。
- 金融時系列は含まない。公開ベンチマーク系列での性能である。

## ライセンス

コードは Apache-2.0 だが、**TimesFM 3.0 の重みは `timesfm-non-commercial-license-v1.0`**
で商用・本番利用は許諾されていない。商用の可能性を残すなら Apache-2.0 の
ままの 2.5 系（`google/timesfm-2.5-200m-pytorch`）を使うことになる。
