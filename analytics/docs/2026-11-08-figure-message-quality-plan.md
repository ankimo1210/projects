# 図表のメッセージを深める

更新：2026-11-08。ユーザー追加要件：「一つずつの図や表のクオリティというか、込めてるメッセージが少ないのでもう少し考えてほしい。」

## 完成条件

各図表を1件ずつ監査し、①読者に発見してほしい数学的主張、②その根拠となる可視の比較/対応/変化、③読み取る手順、④条件と限界、⑤次の判断/応用を記録する。図の存在数、正しい座標、overflow0だけでは合格にしない。

単なる概念のラベル、本文の要約、きれいな曲線だけの図は、具体的な前後/対比/反例/誤差/自由度/情報損失が分かる構成へ改める。図内へ長文を詰めず、値/色/矢印/対応線/補助線/段階パネルと本文近傍の読み方を使う。表には仮定から結論や手順を選ぶ具体例を入れ、本文と同じ説明を重複するだけにしない。

ユーザーが既存の全科目も今回の範囲に含めることを明示承認。対象は本サイト全11科目101章の全静的図表と37実験の主要図。旧4大型教科書の全文改訂は含めず、リンクと接続を維持する。最低図数は維持し、追加枚数を目的にしない。深さがある図表は維持理由を残し、不要な書換をしない。数学本文の説明は図を読める最小限を補う。

## 変更境界と費用

ユーザーの全科目改修承認により、既存91原稿と既存実験UIも必要な教育改修の対象。数学定理/APIを無関係に変えず、原本の図・表・読取り説明へ変更を限定する。追加の入力や数学状態が必要な実験は実装前にrootへ契約を提案する。共通CSS/テーマ/serve/旧4教科書は保持し、新依存/公開/commit/pushなし。Git既存ユーザー変更はsnapshotと差分で保存する。前段の「既存81/91原稿保持」は旧科目を未改修だった時点の記録であり、今回承認された図表変更を禁止する条件とは扱わない。

出力見積：最終102HTML約30MiB、全科目の図表証拠/レビュー計100〜200MiB、原本snapshot約2MiB。巨大配列なし、同じ検証rootを更新し失敗は要約。最終du実測、30GiBには遠い。

## 個別監査と合格判定の運用（Opus設計レビュー対応）

各静的図表と実験の主要図を、id / page / kind / claim（発見）/ evidence（可視根拠）/ readingSteps（読み方）/ scopeLimit（条件と、この図では示さないこと）/ transfer（次の判断。該当なしは理由付き）/ verdict（keep・annotate・redesign）/ keepReason / beforeHash / afterHash / validation の固定項目で保存する。hashは図表fragment単位と章原本単位を残す。既存auditは同項目へ後で対応づけるが、数学/表示合格と教育合格を混同しない。

作者以外が図・caption・title/descだけから主張と根拠を記述し、監査表のねらいと違うなら不合格。有限サンプル/模式図/一例は一般証明とは呼ばず、示さない範囲も必ず記す。図数を増やすための改修をしない。

変更範囲はfigure/svg/figcaption/table/caption、data-reading-noteを付けた読取り段落、ユーザーが追加承認したH2正式名化とcatalog/buildの主題/副題生成。その他のproof/演習/ヒント/解答本文はsnapshotと機械diffし保持を原則とする。既存数学誤りや不足仮定を直す場合は対象と根拠を例外manifestへ明記する。図を参照する本文/数値/左右/色/演習を抽出して再照合し、古い参照を残さない。

支援技術向けtitle/descに主張と根拠、色以外に線種/記号/ラベルを併用し、読み方の説明はNoJSにも置く。QAの既存条件は弱めない。文字bboxに加えて、文字と線を別に描いたインク交差検査を追加し、意図しない新交差0を合格とする。検出候補は実画像で裁定し、意図した接続や偽陽性は根拠・hash付きで記録する。
