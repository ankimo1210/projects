## 1. 欠陥 A — Plotly フレームが「変化しないトレース」を毎フレーム再送信

### 何が起きていたか

スライダー付きの図は、フレームごとにトレース一式を送り直す作りになっていた。
実際には多くの図で **動くのは 1 本だけ** で、残り（データの散布図・密度の等高線・目標曲線）は
全フレームで同一。それが丸ごと複製されて `.ipynb` に埋め込まれていた。

`linear_algebra` では 1 枚の図の JSON 1.45 MB のうち 86% が同じ等高線の複製だった。
同じ構造が 4 教材すべてにあり、`traces=[...]` の指定は **7 モジュール中 0 箇所** だった。

### 直したもの

| 教材 | 図 | 動かないのに毎フレーム送っていたもの |
|---|---|---|
| neural_net | `plotly_decision_boundary` | 学習データの散布図（エポックで変わらない） |
| neural_net | `plotly_function_approx` | 目標関数の曲線（ユニット数で変わらない） |
| bayesian | `plotly_gibbs_path` | 目標密度の等高線 60×60（チェーンだけが伸びる） |
| machine_learning | `plotly_model_complexity` | train/test の散布図（次数で変わらない） |
| machine_learning | 06 章 SVM / 05 章 決定木（ノート内で直書き） | 学習データの散布図 |
| machine_learning | 05 章 ブースティング（ノート内で直書き） | データ点（木の本数で変わらない） |

いずれも静的トレースを `fig.data` に固定し、フレームは `go.Frame(..., traces=[i])` で
動く分だけを運ぶ形にした。

**ノート内で図を直書きしていた 3 セル**（machine_learning 05・06）は、
同じ構造の使い回しだったので `ml_textbook.plotting.plotly_decision_surface_slider` に共通化した。
`surface_fn(grid, value)` を渡すだけで、散布図の固定とグリッドの丸めは helper 側が面倒を見る。

### 数値の丸め

座標・画像・等高線の値は 3〜5 桁に丸めてから埋め込むようにした（`_f()` ヘルパー）。
画面上は区別できないが、`.ipynb` では 1 値あたり 19 文字が 6 文字になる。

**丸めてはいけないものがある**ので、そこは明示的に除外し理由をコメントに残した。

- **残差・特異値のエネルギー比**: 何桁もまたぐ量。絶対値で丸めると小さい側が 0 になり、
  対数軸の図が壊れる。
- **アテンションの softmax 行**: 行和が 1 であることをテストが検査している。
  丸めると `1.0001` になって落ちる（実際に落として気づいた）。
- **分類器の `predict` が返す整数ラベル**: float に直して丸めると `0` が `0.0` になり
  **かえって 3 倍に増える**。最初これで machine_learning が +3% 太った。
  `_f()` は整数値の配列を int のまま出すようにしてある。

### 結果

| 教材 | notebooks 合計 | 最大セル |
|---|---|---|
| neural_net | 15.70 MB → **13.48 MB** (−14%) | 1.60 MB → 0.53 MB |
| bayesian | 10.41 MB → **8.56 MB** (−18%) | 1.97 MB → 0.3 MB 未満 |
| machine_learning | 12.04 MB → **11.79 MB** (−2%) | 3.12 MB → 1.42 MB (−55%) |
| laplace | 6.04 MB → 6.04 MB (±0%) | 変化なし（下記） |

machine_learning の合計が伸び悩んでいるのは、最大の図が半分以下になった一方で、
他の図が丸めの往復でわずかに増えたため。個々の欠陥は解消している。

**laplace は Plotly 図がもともと小さく、容量は別の要因で決まっている。**
上位 3 セル（合計 3.5 MB）は matplotlib の `FuncAnimation` を `to_jshtml()` で
埋め込んだもので、全フレームが base64 PNG として入っている。
これは今回直した欠陥とは別の仕組みで、**縮めるには画質かコマ数を落とすトレードオフが要る**ため、
判断を仰ぐまで手を付けていない（`_plotly_slider` の座標丸めだけ入れた）。

## 2. 欠陥 B — CJK 約物に隣接した `**` が強調にならない

### 何が起きていたか

CommonMark の flanking 規則では、`**` の直後が約物（`「`『`（` など）で、
かつ直前が文字の場合、その `**` は開き記号として成立しない。
結果として **強調がかからず `**` がそのまま表示される**。

`linear_algebra` で 3 箇所見つけて直した欠陥だが、同じ書き癖が他教材にもある可能性があった。

### 検出方法（ここが本題）

ソースを正規表現で探す方法は使えない。候補が 1 教材あたり 200〜290 行出て、
その大半は正常にレンダリングされるからだ。**実際にレンダリングした結果が唯一の真値**。

さらに 2 つの罠があった。

1. **`{admonition}` の中身が走査から抜ける。** 素の CommonMark はこれをコードフェンスとして
   扱うので、中身が「コード」になって検査対象から外れる。ところが MyST は中身を
   markdown として描画する。**そして「核心」コールアウトはまさにこの中にある**
   ＝欠陥が一番出やすい場所が丸ごと死角だった。ディレクティブを展開してから描画する必要がある。
2. **数式の除去が証拠を消す。** `$...$` を正規表現で削ると、`$` の対応がずれた行で
   広範囲を巻き込み、`**` ごと消えてしまう。数式に `**` は出てこないので、除去しない方が正しい。

最終的な手順は「`{admonition}` を展開 → markdown-it で描画 → `<code>`/`<pre>` を除去 →
残った `**` を数える」。既知の壊れた文字列と修正後の文字列で検算してから全体に流した。
仕上げにビルド済み HTML でも確認している。

### 結果

ソース 7 教材・**2,415 markdown セル**を走査:

| 教材 | 壊れていたセル |
|---|---|
| bayesian | **3** |
| その他 6 教材 | 0 |

bayesian の 3 箇所:

- `00_overview` — `**「核心」**コールアウト` → `「**核心**」コールアウト`
- `01_bayes_theorem_and_probability` — `**事前確率（基準率）**を掛けて` → `**事前確率**（基準率）を掛けて`
- `09_model_checking_and_applications` — `**予測性能（LOO-CV）**で` → `**予測性能**（LOO-CV）で`

いずれも約物を強調の外に出すだけで直る。1 つ目は
`要点を一言で示す**「核心」<strong>コールアウト…示す</strong>「実社会では」**` という具合に
**別の場所が太字になっていた**（対応がずれて中間のテキストを囲んでいた）。

## 3. ついでに見つかった欠陥 — 表示数式の区切り

ビルド済み HTML を確認していて、laplace の 2 セルで
`$$ ... $$` が **前後の空行なしで**本文に挟まっているのを見つけた。
MyST はこれをインライン数式として扱い、後続のテキストを数式範囲に巻き込むため、

```
$\( Y(s) = ... \)\( と **一発で** 書けます。分母 \)as^2+bs+c$
```

のように数式も本文も壊れ、巻き込まれた `**一発で**` の強調も失われていた。

- `laplace/04_solving_odes_with_laplace` cell 3
- `laplace/08_applications_probability_signals_finance` cell 3

前後に空行を入れて修正。全 7 教材を走査して他に該当なしを確認済み。

## 5. 意図的に手を付けていないもの（2026-08-01 に判断済み）

以下は「やり残し」ではなく、**トレードオフを検討したうえで現状維持と決めたもの**。
再訪する人が同じ検討を繰り返さないように、判断と理由を残しておく。

- **laplace の `to_jshtml` アニメーション 3 本（合計 3.5 MB） → このまま。**
  縮めるには `dpi` を下げるかコマ数を減らすしかなく、どちらも教材の見え方を落とす。
  容量よりアニメーションの質を優先する。
- **machine_learning の残る大きい図（06 章 SVM 1.42 MB / 05 章 決定木 0.57 MB） → このまま。**
  決定面の解像度 `grid_steps=120` を落とせば縮むが、境界の滑らかさが落ちる。
  **画質は下げない**方針。冗長性の除去（欠陥 A）はすでに済んでおり、
  残っているのは正味の情報量なので、これ以上は削らない。
- **`ml_textbook/interpretation.py:113` の `B007` と `plotting.py` の `RUF015` → 未対応。**
  どちらも動作に影響しないスタイル指摘（未使用のループ変数、`list(x)[0]`）で、
  今回の変更以前から存在する。なお `make lint`（リポジトリ全体の `ruff check .`）は
  現時点で 240 件のレッドで、その大半は analytics 外
  （kaggle/house_prices 46、aisan_lbo_case 36、deep_hedge_price/notebooks 34 ほか）。
  ワークスペース全体のリント整理は範囲が別なので、別タスクとして扱う。
