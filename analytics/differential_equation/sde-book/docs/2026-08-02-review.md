## A. 重大（本文の主張と図が食い違う / 結論が偏る）

### A-1. ch2 スケーリング実験室で、3枚のうち2枚が実質的に読めない

`app/sde-textbook.tsx:466-497`

3パネルが `sharedDomain` を共有し、その幅を `3.5σ√T` に固定している。既定値
(σ=0.3, T=1, steps=128) では:

| パネル | 終端 sd | 表示域 [−1.05, 1.13] |
|---|---:|---|
| `Δt` 尺度 | 0.027 | ほぼ平坦な直線 |
| `√Δt` 尺度 | 0.30 | 適正 |
| 無尺度 | 3.39 | 大半がクリップされ枠外 |

「消える・残る・爆発する」を見せるのが ch2 の核心なのに、消える側は平坦な線、爆発する側は
枠を突き抜ける縦線にしか見えない。**この本の最初の数値実験が、本文の中心的主張を実演できていない。**

対応案: パネルごとに独立ドメインを取り、各パネルに終端 sd を数値表示して比較させる。
あるいは共通の対数軸にする。

### A-2. ch42 の確率的 SIR が、大流行を過大評価し「初期の偶然消滅」を過小評価する向きに偏っている

`app/application-labs.ts:47-60`（`binomial`）、`:570-580`（`simulateSir`）

`binomial()` は試行数 `n > 48` で正規近似 `round(np + √(np(1-p))·Z)` に切り替わる。
既定値 (N=120, I₀=4, β=1.6, γ=0.65, steps=300) の初期段階では
`susceptible = 116 > 48` なので感染イベントが正規近似で引かれるが、このとき `np ≈ 0.21` で、
正規近似が最も壊れる領域にある。

- 真の Binomial: `P(感染≥1) = 1-e^{-0.206} = 0.186`
- 実装の正規近似: `P(round(0.206+0.454Z) ≥ 1) = 0.259`

**約 40% 過大**。一方で回復イベントは `infected = 4 ≤ 48` なので厳密に引かれる。
つまり感染だけが水増しされ、**「R₀>1 でも偶然消滅する」という ch42 の主題と逆向きにバイアスがかかる。**
`applicationMetrics` の「標本大流行率」と「初期分枝近似」の比較（`:1450-1456`）は、
まさにこの差を読者に見せる指標なので、系統誤差がそのまま結論に乗る。

対応案: `np < 10` のときは既存の `poisson(random, n*p)` を `n` でクランプして使う（1行で済む）。

### B-4. ch40 の図は Gillespie ではない

`app/application-labs.ts:378-391`

実装は固定グリッド上の厳密遷移核（immigration–death の Binomial+Poisson）で、これは
**手法として正しく、しかも高速**。ただし章の本文は「これが Gillespie 直接法です」と書き、
notice は「Gillespie 経路は整数値で**反応時刻にだけ跳び**」と述べる。実際の図はグリッド時刻でしか
跳ばず、1ステップ内の複数反応は見えない。本文か図のどちらかを合わせる必要がある。

### B-5. ch22 の裾比較で α-stable だけ標準化されていない

`app/extended-labs.ts:382-409`

Gaussian は単位分散、複合 Poisson は `√κ·σⱼ` で標準化しているが、
`stable` は `Math.abs(symmetricStable(random, alpha))` の生値。x 軸ラベルは「標準化閾値 |z|」。
α<2 に分散が無い以上「標準化」が一意でないのは事実だが、現状では**見えている裾の差の一部が
尺度差であって裾指数の差ではない**。せめて IQR や中央絶対偏差で揃えるか、
「stable は尺度を揃えていない」と明示すべき。

### B-6. 閾値を明示せよと書いた章が、閾値を表示していない

`app/application-labs.ts:638-640`、`:693-700`

ch42 本文:「『流行』を累積感染者数の閾値で定義する場合、**その閾値も結果と一緒に示します**」。
実装は `outbreakThreshold = max(0.2N, I₀+10)` を内部で決め打ちし、図には
`大流行 XX%` としか出さない。自分の書いた作法を自分で破っている。

### B-7. 描画のたびに全シミュレーションが2回走る

`app/sde-textbook.tsx:2473-2475`（draw）と `:3250-3423` / `extendedMetrics` / `applicationMetrics`

`metricsFor` が draw と同じ診断関数をもう一度呼ぶ構造になっており、
`firstPassageDiagnostics` / `feynmanKacDiagnostics` / `deltaHedgeDiagnostics` /
`milsteinDiagnostics` / `epidemicDiagnostics` など重い関数が**毎レンダで2回**実行される。

さらに `CanvasLab` の `draw` は `ResizeObserver` にも直結している（`:2477-2484`）ので、
ウィンドウのドラッグリサイズ中に `deltaHedgeDiagnostics`（6刻み × 160経路 × 最大128ステップ、
各ステップで `normalCdf` を2回）が連続実行される。デバウンスも `useMemo` もない。

対応案: 診断結果を `useMemo([lab, settings])` で1回だけ計算し、`drawLab` と `metricsFor` の
両方へ渡す。ResizeObserver 側は再計算せず再描画のみにする（現状は再計算まで巻き込む）。
A-5 の図と数値のずれも、この一本化で同時に消える。
