# Stage 2E / B11 implementation plan

## 結論

B11は原典の「Liquidity-Aware Intraday JGB Curve」をそのまま実装しない。JGB intradayの
bid/ask、約定、先物、CTD、repoを取得できないことは既にfeasibility gateで確認済みであり、
架空の市場を作って実証結果に見せない。

代わりに、既存の公式U.S. Treasury daily par-yield snapshotを中心に、FINRA TRACE Treasury Daily
Aggregate Statisticsは**API access/terms gateが通った場合だけ**使う
**Treasury Curve Forecast-to-Decision Specification**へ再設計する。公開集計で識別できるvolume・
trade count・venue channel・on/off-the-run・一部VWAPと、識別できないtrade-level spread・slippage・
impactを明確に分離する。Web画面のscrapeは採用せず、未承認時のWeek 42はquote fixtureによる
式・単位検証へ縮小する。

## Data feasibility

| Source | 利用可能な観測 | Coreで許す主張 | 許さない主張 |
|---|---|---|---|
| U.S. Treasury Daily Par Yield Curve | 3m/2y/5y/10y/30y、日次、percent | yield-change prediction、curve exposure risk | transaction return、zero curve、executable quote |
| FINRA Treasury Daily Aggregates | trade count、par volume、channel、on/off-the-run、一部VWAP | API gate通過後のactivity composition、公開集計のdata contract | bid–ask spread、queue、individual impact、implementation shortfall |
| SEC PIT panel | filing/fundamental availability | cross-sectional prediction protocol | asset return、causal alpha、tradability |

公式Treasury curveはindicative bid-side quotationsから作るpar curveで、actual transactionでも
zero-coupon curveでもない。FINRA daily aggregatesは2023-02-13以降の翌日公開集計であり、
transaction-level order bookではない。

## Week design

### Week 41 — Signal research without alpha inflation

- real Treasuryでformation lag、time-series signal、multiple testing、backtest overfittingを扱う
- cross-sectional/Fama–MacBethは数式・API・known-truth validationまでとし、SEC fundamental
  predictionをasset pricing resultと呼ばない
- primary metric、candidate count、falsificationをsignal計算前に固定する
- outputはforecast evidenceでありP&Lではない

### Week 42 — Observable liquidity and execution boundaries

- FINRA aggregate snapshotでtrade count、par volume、ATS/interdealer対dealer-to-customer、
  on/off-the-run compositionを分析する
- quoted/effective/realized spread式はtrade-level quote fixtureで単位検証する
- half spread、temporary/permanent impact、delay、fundingは明示scenarioとしてのみ計算する
- aggregate volumeからspreadやKyle lambdaを逆算しない

### Week 43 — Fixed income measure and control boundary

- par yield、discount factor、zero/forwardを区別し、Treasury daily curveをzero rateとして使わない
- pricing measureとforecasting measureを分離する
- short-rate/HJMはno-arbitrage restrictionの導出、実証calibrationはAdvanced
- stochastic controlはfinite-horizon backward inductionをCore、HJB/RLをAdvancedとする

### Week 44 — Portfolio decision under estimation and cost uncertainty

- real Treasury yield-change covarianceをcurve exposure allocationへ使う
- covariance shrinkage、turnover penalty、risk budget、sensitivityを診断する
- weightsはyield-change exposureでありcash security portfolio/PnLではない
- causal overlayはtreatment、overlap、outcome、policy loggingが揃う場合のみに許す

## Final project

**Treasury Curve Forecast-to-Decision Specification**を作る。model winnerやproduction strategyは
作らず、以下をfreezeする。

1. economic hypothesisとinformation timestamp
2. official data sources、availability、methodology break
3. forecast targetとbaseline ladder
4. decision mappingとcurve exposure unit
5. observable liquidity fieldsとscenario-only costs
6. primary metric、multiple-testing rule、falsification
7. capacity・crowding・fundingに必要だが不足するdata
8. no-model-selected / no-tradability-claim failure criteria

## Implementation order

1. `quant_specialization.py`: protocol、formation lag、spread identities、scenario cost、
   shrinkage allocation、finite-horizon control
2. FINRA aggregate API access/terms gate、fetch/parse/snapshot contract（外部取得はbuild時のみ、Notebookはoffline）。
   gate未通過ならWeek 42はfixture-onlyとする。
3. Week 41–44 / overview / Projectの6 deterministic builders
4. curriculum、TOC、READMEをB1–B11 / Week 1–44 / 66章へ同期
5. tests、clean-kernel execution、warning-as-error HTML build
