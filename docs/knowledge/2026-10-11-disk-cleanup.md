# ディスク容量の整理と保護したデータ

確認日: 2026-10-11（日本時間）。容量は GiB（2^30 bytes）。
Windows のボリューム情報・ファイルメタデータ、WSL の `du` / `df`、Git の状態から確認した。

## 結果と整理候補

C: の空きは作業開始時 3.74 GiB、途中で 0、18:36 の確認では 49.73 GiB。
他のプロセスも動いているため、この前後差をすべて本作業の効果とは扱わない。

| 候補 | 実施したこと | 容量・件数 | 検証 |
|---|---|---:|---|
| 古い NVIDIA シェーダーキャッシュ | 7日以上更新されていないファイルを外付け F: へ退避 | 20.10 GiB / 466件 | 移動前後の SHA-256 が一致。移動できなかった9件は保持 |
| 古いダウンロード済みインストーラ | CUDA / Anaconda のキャッシュを F: へ退避 | 4.61 GiB / 2件 | SHA-256 が一致 |
| 古い Visual Studio インストール一時データ | 使用プロセスがないことを確認して F: へ退避 | 3.47 GiB / 721件 | 全件 SHA-256 が一致 |
| WSL のクラッシュダンプ | 診断用に F: へ退避 | 3.65 GiB / 3件 | 全件 SHA-256 が一致。内容は公開しない |
| uv ダウンロードキャッシュ | `uv cache clean --offline` で削除 | CLI 報告 50.1 GiB / 265,837ファイル | 共有 `.venv` の主要 import と `uv lock --check --offline` が成功 |
| main に取り込み済みの worktree | 6件を通常の `git worktree remove` で整理 | 6件 | クリーン・main への包含・非稼働を確認。キャッシュ以外の無視ファイルは TAR に保存し内容ハッシュを照合 |

Windows 側は直接削除操作が自動承認レビューで拒否されたため、復元可能な退避を選んだ。
F: の空きは 169.46 → 136.68 GiB。退避は C: の容量を減らすが、全ドライブの合計使用量を減らすものではない。
個人データの中身・詳細な保存先、クラッシュダンプや退避マニフェストはこの公開リポジトリに保存しない。

## 保護したもの

- main の未コミット変更、未追跡ファイル、既存の Git ブランチとコミット履歴。
- 未マージの worktree 3件: `johnhull-research-roadmap`、`johnhull-storage-codec`、`m21`。
- `johnhull-research-roadmap/.superpowers/` の約115 GiBの研究実験データ。未マージ作業に属するため、不要と断定して削除しない。
- 端末バックアップ・写真・ゲーム・利用中のモデル・Docker のデータ。
- 使用中または最近更新されたキャッシュ。

退避先には移動マニフェストと worktree ごとの HEAD / ブランチ・無視ファイルのハッシュを保存した。
取り込み済みの worktree はブランチまたは HEAD から再作成し、保存した TAR を戻せる。

## WSL の空きと C: の空きは別

オンラインの `fstrim -v /` は成功（502.3 GiB trimmed）。
これは通知した未使用領域であり、Windows で回収した容量ではない。
Ubuntu の VHDX は処理後も論理サイズ・割り当てサイズともに 602.39 GiBだった。

Windows に WSL の空きを返す仕上げは、[既存の圧縮手順](2026-09-16-wsl-vhdx-compaction.md)に従う。
保存済み・稼働中の作業がないことを確認し、Ubuntu を停止して管理者権限で実施する。
今回は別セッションの未マージブランチの更新を検出し、Windows の管理者権限もないため、停止・圧縮は実施していない。
スパース化を強制するオプションは使わない。

## 検証の範囲

- Windows の退避ファイル、worktree の保護対象を内容ハッシュで照合した。
- キャッシュ削除後に NumPy / pandas / PyTorch / LINE解析パッケージの import が成功。
- `uv lock --check --offline` が成功（334 packages）。
- ソース・依存関係・CI を変更していないため、ワークスペース全体テストは実行していない。
