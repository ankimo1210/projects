# Codex 利用上限の API 料金相当額

確認日: 2026-10-09（日本時間）。このアカウントの実際のサブスク利用ログでは、
毎週の枠を使い切る場合の API 料金相当額は **約950〜1,000 USD／30日**が目安だった。
サブスクの請求額や公式のドル建て上限を表す数値ではない。

## 観測結果

集計期間は2026-10-07 12:59:39〜2026-10-09 20:39:33（日本時間）。
取得できた上限は7日間（10,080分）で、月間上限ではなかった。
トークン使用記録4,719件を集計し、枠の使用率は0%から61%へ増えた。
モデルは GPT-6.1 Sol が4,677件、GPT-6 Astra が42件。

| 集計区間 | 使用率の増加 | API料金相当額 | 週上限への換算 | 30日への換算 |
|---|---:|---:|---:|---:|
| 全期間 | 61ポイント | $141.413814 | $231.83 | $993.54 |
| 20%から40% | 20ポイント | $43.9620844 | $219.81 | $942.04 |
| 40%から60% | 20ポイント | $43.9363928 | $219.68 | $941.49 |
| 49%から60% | 11ポイント | $24.3704000 | $221.55 | $949.50 |

20%から40%の区間で求めた「1ポイントあたりのAPI料金相当額」を使うと、
後の49%から60%の区間の消費は11.087ポイントと予測できた。
表示上の実測は11ポイントで、差は0.087ポイントだった。
区間の近い結果は推定の整合性を示すが、将来の誤差保証や信頼区間ではない。

## 計算方法と検証

入力593,680,062トークンのうち、574,870,144トークンがキャッシュ入力。
出力は4,078,849トークンだった。推論トークンは出力に含まれるため再加算しない。
記録上のキャッシュ書き込みは0で、各リクエストの入力は272,000トークン以下。
速度の明示記録がないため、APIの Standard 料金を換算の前提とした。

2026-10-09に確認した、100万トークンあたりの料金は次のとおり。

| モデル | 通常入力 | キャッシュ入力 | 出力 |
|---|---:|---:|---:|
| GPT-6.1 Sol | $2.00 | $0.10 | $10.00 |
| GPT-6 Astra | $10.00 | $1.00 | $50.00 |

各リクエストについて、`I`を入力、`C`をキャッシュ入力、`O`を出力、
`r`を上表の単価として、料金相当額を計算して合計した。

```text
API料金相当額 = ((I - C) × r_input + C × r_cached + O × r_output) / 1,000,000
週上限の相当額 = 区間のAPI料金相当額 / (使用率の増加ポイント / 100)
30日の相当額 = 週上限の相当額 × 30 / 7
```

累積使用量が変わらない通知1,030件を除外し、日時と使用量が同じ記録の重複を確認した。
比較可能な4,674件では、累積使用量の差分と直近リクエスト使用量が一致した。
通常入力・キャッシュ・出力・書き込み・長文料金の数値例と集計を検証し、
浮動小数点での集計結果を Decimal でも再計算した。
新規の有料API呼び出し、追加クレジット購入、利用枠リセットは行っていない。

## 推定の条件と再測定

この推定は、観測時のモデル構成・入力と出力の比率・キャッシュ率が続き、
毎週の通常枠を使い切ることを前提とする。追加クレジットや臨時リセットは含まない。
サブスク枠の消費とAPIの請求料金は別体系であり、モデルや速度、キャッシュ率が
変わるとAPI料金相当額も変わる。

使用率は1%単位で、同じアカウントの並行タスクが枠を共有する。
別端末やクラウドの利用が手元のログに含まれない場合は過小推定になる。
金額の小数桁は計算結果を示すもので、上限の測定精度を示さない。

再測定では、公式単価と利用枠の期間を確認し、同じリセット期間のトークン記録を
上の式で集計する。使用率が十分に増えた複数区間を比較し、後の区間で換算の
整合性を確認する。単一タスクの制御実験には、他の同時利用を止めた条件が必要。
会話本文・認証情報・アカウントIDを共有ノートやGitへ保存しない。
