# Claude 利用上限の API 料金相当額

確認日: 2026-10-17（日本時間）。プランは Claude Max 5x。
Claude Code（Opus 5.5、effort xhigh）の実測では、**5時間枠は約60 USD**（54〜63 USD）、
**週枠は暫定で約270〜440 USD**が API 料金相当額の目安だった。
サブスクの請求額や、公式のドル建て上限を示す数値ではない。

## 観測結果

5時間枠は 2026-10-17 11:10〜16:10、週枠は 2026-10-12 14:00〜10-19 14:00（日本時間）。
`L` は 5時間枠の開始からこの Mac の全セッションで使った API 料金相当額の累計。

| 日本時間 | L | 5時間枠 | 週枠 |
|---|---:|---:|---:|
| 14:42:11 | $1.835 | 6% | 1% |
| 14:42:44 | $2.041 | 7% | 1% |
| 14:48:24 | $3.561 | 9% | 1% |
| 14:49:55 | $4.756 | 10% | 1% |
| 15:04:35 | $6.761 | 15% | 2% |
| 15:07:06 | $7.427 | 16% | 2% |

7%（14:42:44）から16%（15:07:06）までの9ポイントで5.44 USD を消費し、
1ポイントあたり0.604 USD、5時間枠全体では約60 USD になる。
使用率は1%単位なので、始点は7.0〜7.4%、終点は16〜17%の幅がある。
増加分を8.7〜10ポイントとみると、5時間枠は54〜63 USD になる。

この区間の消費は、1時間キャッシュ書き込み230,193トークン（1.84 USD）、
キャッシュ読み込み5,089,246トークン（1.02 USD）、出力128,976トークン（2.58 USD）、
通常入力96トークン。主な作業は会話セッション1本と、測定用の
読み取り専用 `claude -p` 2回（1.02 USD と 2.74 USD）。

週枠は1%から2%への変化を1回見ただけで、区間の差から直接は求められない。
同じ時点の5時間枠と週枠の使用率の比から推定した。

- 15:04:35 では5時間枠が15〜16%、週枠が2〜3%なので、比は5〜8倍。
- 14:49:55 では5時間枠が10%以上、週枠が2%未満なので、5倍より大きい。
- 14:42:11 では5時間枠が7%未満、週枠が1%以上なので、7倍より小さい。

比を5〜7倍とすると、週枠は約270〜440 USD、30日換算で約1,160〜1,890 USD。
この推定は、週枠の使用分がほぼこの5時間枠に収まる前提に立つ。
今週ほかの日や端末で使っていれば週枠の使用率が高めに出て、上限は過小推定になる。

## 区間ごとのばらつき

| 区間 | 消費 | 1ポイントあたり |
|---|---:|---:|
| 7%から9% | $1.520 | $0.760 |
| 9%から10% | $1.195 | $1.195 |
| 10%から15% | $2.005 | $0.401 |

10%から15%の区間は、思考を含む出力90,593トークン（1.93 USD）の1回の呼び出しが大半を占め、
API料金のわりに使用率が速く増えた。出力の多い作業ほど、上限のドル換算は小さくなる可能性がある。
1ポイント刻みの区間は丸めの影響が大きいため、上の推定には区間全体の傾きを使った。

## 計算方法と検証

2026-10-17に確認した、100万トークンあたりの料金は次のとおり（Opus 5.5 と Sonnet 5.5 の
キャッシュ読み込みは基本入力の0.05倍、ほかのモデルは0.1倍）。

| モデル | 通常入力 | 5分キャッシュ書込 | 1時間キャッシュ書込 | キャッシュ読込 | 出力 |
|---|---:|---:|---:|---:|---:|
| Opus 5.5 | $4.00 | $5.00 | $8.00 | $0.20 | $20.00 |
| Sonnet 5.5 | $2.00 | $2.50 | $4.00 | $0.10 | $10.00 |
| Fable 5.1 | $10.00 | $12.50 | $20.00 | $0.25 | $50.00 |

各応答について、`I` を通常入力、`W5`・`W1` を5分・1時間のキャッシュ書き込み、
`C` をキャッシュ読み込み、`O` を出力、`r` を上表の単価として合計した。
`inference_geo: "us"` は1.1倍、fast mode は2倍として扱う（今回の記録はすべて global・standard）。

```text
API料金相当額 = (I × r_input + W5 × r_5m + W1 × r_1h + C × r_cache + O × r_output) / 1,000,000
5時間枠の相当額 = 区間のAPI料金相当額 / (使用率の増加ポイント / 100)
30日の相当額 = 週枠の相当額 × 30 / 7
```

1つの応答が複数行に分かれて記録されるため、メッセージIDとリクエストIDで重複を除いた。
この計算は Claude Code 自身の表示額（statusline の `cost.total_cost_usd`、
`claude -p` の `total_cost_usd`）と2%以内で一致し、`claude -p` 1回分では完全に一致した。
新規の有料 API 呼び出し、追加クレジットの購入、利用枠のリセットは行っていない。

## データの取り方

- statusline に渡される JSON の `rate_limits.five_hour` / `rate_limits.seven_day`
  （`used_percentage` と `resets_at`）を、値が変わるたびに
  `~/.claude/usage-log/rate-limits.jsonl` に追記する（`~/.claude/statusline-command.sh`）。
- 使用率は API のヘッダー（`anthropic-ratelimit-unified-5h-utilization` など）由来で、
  小数2桁の比率、つまり1%単位。
- `claude -p --output-format stream-json --verbose` でも `rate_limit_event`
  （`unifiedWindows` の `utilization`）が出るが、値が変わったときだけ出る。
  stream-json の `assistant` 行の usage は出力トークン数が確定前のことがあるため、
  料金はディスク上の会話記録から計算する。
- 料金の集計は [`claude-usage/api_cost.py`](claude-usage/api_cost.py)、
  使用率の記録との突き合わせは [`claude-usage/analyze_log.py`](claude-usage/analyze_log.py)。

```bash
python3 docs/knowledge/claude-usage/analyze_log.py
python3 docs/knowledge/claude-usage/api_cost.py 2026-10-17T02:10:00Z 2026-10-17T06:07:06Z
```

## 推定の条件と再測定

利用枠は claude.ai と Claude Code、すべての端末で共有される。手元で料金に換算できるのは
この Mac の Claude Code の記録だけなので、同じ区間にほかで使うと使用率だけが増え、
1ポイントあたりの金額は過小推定になる。今回の5時間枠は、この Mac の最初のセッション（11:31）より前の
11:10に始まっており、ほかでの利用があった。測定区間（14:42〜15:07）にほかで使っていないことは未確認。

推定は、観測時のモデル構成、キャッシュ率、出力の比率が続くことを前提とする。
公式には、Max 5x は Pro の5倍のセッション枠を持ち、5時間ごとのリセットと別の週枠があるとだけ
説明されており、トークン数やドル建ての上限は公表されていない。

再測定では、数日ふつうに使ってから `analyze_log.py` を実行し、週枠も同じリセット期間内の
最初と最後の変化点で直接求める。使用率が十分に増えた複数区間で値が近いことを確認する。
会話本文、認証情報、アカウントIDは共有ノートや Git に保存しない。
