## 3. 直す規則（PREREG §5 に、計算の前に書く）

ETF・株・SPDR のすべての系列に、次の順番で当てる。直したものは、規則・系列・日付・項目・前後の値を `results/corrected/corrections.json` に一覧にする。

| 規則 | 条件 | 直し方 |
|---|---|---|
| C2 始値0 | 出来高が正なのに始値が0 | 始値を欠損にする（O2C・C2O が欠損になる） |
| C1 桁の跳び | 分割の記録のない日 d に、終値がその系列の前の行の終値の2倍超か1/2未満 | d をまたぐリターン（C2O・C2C・シグナルの C2C）を欠損にする。価格の水準は変えない |
| C4 分割の日の配当 | 分割の記録（比 k）と同じ日の配当 D | 次の2つがどちらも D/k を指すときだけ、D を k で割る。①D/k が D よりその系列の直前の配当に近い（対数の差）。②前日終値 P に対する D/(kP) が D/P よりその日の下落に近い。下落は、株の中央値の配当込みの C2O から、その系列の始値÷前日終値−1 を引いたもの。直前の配当がなければ D のまま |
| C5 終値を超える配当 | D が前日終値より大きい | その系列の、d より前で最も新しい C1 の跳びが下げ（終値が1/2未満になった）なら、その跳びの大きさ（前の終値÷終値。1629.T の 2015 年は約506）で D を割る。割ってもまだ前日終値より大きいか、そういう跳びがなければ、D を0にする |
| C6 ETF の配当日 | NEXT FUNDS（1617〜1633.T）の配当 | 記録の日と、その ETF の行の前の2営業日のうち、「ETF の始値÷前日終値−1 から株の中央値の配当込みの C2O を引いたもの」の17本の平均（出来高のあった本だけ）が一番低い日に、配当を移す |
| C3 行の欠け | 上場中（最初の行から最後の行まで）の ETF に行がない日本の営業日 | その日をシグナルの行（窓と $C_\text{full}$）から外す。ETF のシグナルの C2C は、次の行で前の行からの2日分にする。株とバスケット、評価する日は変えない |
| C7 シグナルの日本側 | — | yfinance の配当込み終値をやめ、直した終値と配当から C2C =（終値＋配当）÷前の行の終値−1 を作る。出来高ゼロの日も値を使う（記録と同じく、ほとんどは変化0）。C1 の日は欠損 |

- 規則は、パネルの期間（2009-06-01 から）の、各市場の営業日に並べた値に当てる。「前日終値」はその系列の前の営業日の終値、C1 の「前の行」は行のない日を飛ばした前の終値、C4 の「直前の配当」はその期間で d より前の最も新しい配当。
- 米国の SPDR は、記録と同じく配当込み終値の C2C を使い、C1 だけを当てる（誤りは見つかっていない。C1 も0件）。
- 2倍という閾値は、実データを見て決めた。パネルの期間で2倍を超えるのは、§2 の誤り（1629.T の3日と 8227）と、8303 の上場廃止と再上場の2日、9201 の 2010 年（株価1〜5円）の2日と 2012 年の再上場だけだった。
- C4 を最初の案（その日の下落だけで決める）から改めた。分割と同じ日の配当はパネルの期間に320件あり、最初の案では193件を割る。3月と9月は株がいっせいに権利落ちするので、株の中央値の始値の下落にふつうの配当がすでに入り、比べる下落が小さく出る。さらに1銘柄の朝の値動き（±1〜2%）が配当利回りの差より大きい。たとえば 1605 の 2013-09-26 の配当 ¥9 は正しく調整されているのに、400 で割ってしまう。今の C4 は47件を割る。既知の3件を含み、D/P が4%を超える14件のうち11件を含む。残りの3件は、9101 と 9107 の 2022-09-29（海運の実際に大きかった配当、D/P 11.8% と 4.5%。割らないのが正しい）と、8174 の 2026-09-29（D/P 5.4%。その日の下落 4.5% が D/P に近いので割らない）。
- C6 は、2013〜2026年の毎年、記録の日の1〜2営業日前を選ぶ（2019年までは2営業日前、2020年からは1営業日前）。14回とも17本すべてが同じ日に移る（それより前の配当は yfinance にない）。選んだ日の差の平均は −0.8〜−3.9%、ほかの候補の日は ±0.8% 以内。物差しを株の中央値の配当込みの C2O にしても、配当を含まない始値の比のままでも、選ぶ日は同じ。
- 規則を当てたあと、既知の誤り（§2 の表の全行）がどれかの規則で直ったかを確かめる。1つでも直っていなければ、そこで止めて報告する。確かめる中身（規則・系列・日付・件数）は実装計画が決める。2026-10-19 の snapshot では、C2 53件・C1 9件・C4 47件・C5 13件・C6 238件・C3 16件で、既知の誤りはすべて直る（計画を書く途中の確認。段はどれも回していない）。

## 4. 手順と関門

1. `corrections`：§3 の規則を当て、`results/corrected/corrections.json` を書き、既知の誤りの確認をする。結果（シグナルと価格の関係）は何も計算しないので、PREREG §5 の commit の前に回してよい。既知の誤りの確認が通ってから、PREREG §5 を commit する。
2. `run g0 --data corrected`（並べ方の選択を含む）。
3. `run g1 --data corrected`。
4. 直した G0・G1 の結果を PREREG §5 に書き足して commit する。
5. `run main-a --data corrected`。その結果を commit する。
6. `run main-b --data corrected` を1回だけ回す（`results/corrected/main_b.lock`）。2回目は `--rerun-reason` が要り、読み方には最初の1回を使う。
7. `run diagnostics --data corrected`。
8. `report`。

関門（記録と同じ形に、次の2つを足す）：

- 直したデータのどの段も、PREREG の最後の commit が記録の `results/main_b.json` の commit より新しく、PREREG に §5 があることを求める。
- 生データの `inputs_digest` が、記録の `results/main_b.json` の `meta.inputs_digest` と同じことを求める（同じ snapshot を直したことを保証する）。`corrections` も同じ。
- 直したデータのどの段も、`results/corrected/corrections.json` が既知の誤りの確認に通っていて、その一覧が、いま規則を当てて出る一覧と同じことを求める（実装計画で足した）。
- 記録と同じく：G0 で並べ方が選ばれなければ（`replication_failed`）止める。G1 が不合格なら止める。本番 A は、G1 を回したあとの PREREG の commit を求める。本番 B は、`results/corrected/main_a.json` の commit を求める。

## 5. 読み方（PREREG §5 に、計算の前に書く）

- 主に見るのは、直したデータの判定（`results/corrected/main_b.json` の `verdict`）が、記録の `usable` と同じかどうか。
  - 同じなら `verdict_robust`。
  - 違えば `verdict_data_dependent`。①〜④と、G0・G1 のどこが変わったかを書く。G0 か G1 で止まった場合と、並べ方が変わった場合も含む。
- 並べて報告するだけにするもの：並べ方、G0 の AR と係数、H1 の係数と t、比の区間、H2 の平均と p（基準・2bp・5bp）、本番 B の平均、H3、取引時間の延長の前後、分解（C2O・C2C は直したデータで初めて読める）。
- 記録の判定は `usable` のまま変えない。README には両方を書く。

## 8. テスト

- `corrections.py`：
  - C1：分割の記録のない2倍超の跳びでリターンが欠損になり、跳びのない日は変わらない。分割の記録のある日は跳びとみなさない。
  - C2：始値0の行の O2C・C2O が欠損になる。
  - C3：行のない日がシグナルの行から外れ、次の行の C2C が2日分になる。
  - C4：直前の配当と下落の両方が D/k を指すときだけ割る（割る場合、片方だけが指す場合の両方）。下落は株の中央値と比べる。
  - C5：前の下げの跳びの比で割る場合と、0にする場合。
  - C6：下落の一番大きい日に配当が移る。17本が同じ日に移る。
  - C7：直した終値と配当からの C2C が、誤りのない系列では記録の配当込み終値の C2C と一致する。
- 誤りのない合成データ（テストの `decayed_world`）では、規則は何も変えず、直したデータの判定が記録の判定と同じになる。
- CLI：§4 の関門がそれぞれ理由つきで止める。結果は `results/corrected/` にだけ書かれ、記録のファイルは変わらない。
- 要約：記録と並べた表が出て、`nan` が出ない。

## 9. 既知のリスクと限界

- 規則は、誤りを見たあとに決めた。直したデータでの結果は、規則を決めた時点で何も見ていない。閾値（2倍）は実データの分布を見て決めた。C4 は、規則を実データに当てて（何を直すかだけを見て）改めた。そのときも、直したデータで段はどれも回していない。
- 直せない誤りがある。2025-10-24 の16本の値そのもの（C3 で2日分の C2C にするだけ）と、8303 の本当の配当額（0にする）。
- 2015-12-25 と 2016-07-11（東証は開いていたが、yfinance の株のほとんどが出来高0）は、規則では直さない。日本の営業日から外れたままで、評価する日が2日少なく、次の営業日の ETF のシグナルの C2C と株の C2O・C2C が2日分になる（記録と同じ）。
- C1 は本当の値動きも外す。9201 の 2010 年の2日と 2012 年の再上場の日（本番 A より前）。
- 8227 の分割は、記録の日（02-19）より前の価格が調整されていないので、H2 の株数を決める価格（分割を戻した値）が3倍になる。8227 は100株の金額が1銘柄の予算を超えるので、記録でも直したデータでも買わない。この規則では直さない。
- 規則が拾うのは、閾値を超える誤りと、§3 の型の誤りだけ。小さな誤りは残りうる。
