# 0004. 大容量成果物を Git 外の検証可能な保管庫へ分離する

- Status: Accepted（保管方針を決定。移管・復元ツールは未実装）
- Date: 2026-09-27
- Related: [整理計画](../superpowers/plans/2026-09-27-workspace-cleanup.md)、[市場分析設計](../superpowers/specs/2026-09-27-market-research-design.md)

## Context

画像、抽出本文、翻訳、保存済みの評価提出物が Git に蓄積している。特に johnhull は
受入済みの節を毎回撮り直すと、再検査証跡の増加が節数に対して二次的になる。
一方、翻訳や人手監査・モデル提出物は同じ結果を再生成できるキャッシュではない。
ユーザーから保管先の選択を委任されたため、追加契約の不要なローカル保管庫を選ぶ。

## Decision

### 保存先

以下のフォルダーは**作成予定**。2026-09-27 に確認したのはドライブの存在と空き容量までで、
保管庫の作成、バックアップ、ファイル移動はまだ行っていない。

| 役割 | 選定した場所 | 理由 |
|---|---|---|
| 成果物の正本 | Windows `F:\ProjectArtifacts\projects` | USB 接続の別の物理 SSD。約175 GiB の空きがあり、現在の対象群を保管できる |
| 検証済みの第2コピー | Windows `%USERPROFILE%\ProjectArtifacts\projects-backup`（C:） | 内蔵 SSD 上の別コピー。約383 GiB の空き。F: の脱落・故障から復元する |
| 日常の計算・DB・ダウンロードキャッシュ | WSL 内の各プロジェクトの既存 Git 除外領域 | 稼働中の DuckDB や作業ファイルを着脱式ドライブに直接置かない |
| ソース・小さな fixture・manifest・検証要約 | Git | 通常のレビューと軽量なオフライン検証を保つ |

空き容量は時点値。移管時に空きと接続先の物理ディスクを再確認する。
C: と F: は同一 PC に接続されるため、災害・盗難に対する遠隔バックアップではない。
当面はこの2コピーを必須とし、クラウド契約・公開アップロード・Git LFS は導入しない。

### Windows / WSL のパスを混同しない

- アプリ側には環境変数 `PROJECTS_ARTIFACT_STORE` と `PROJECTS_ARTIFACT_MIRROR` で渡す設計とする。
  Windows プロセスには Windows パス、WSL プロセスには WSL パスを設定する。
- WSL の保管先は Windows のパスを `wslpath -u` で変換し、ドライブのマウントと実在を確認してから使う。
  文字列の置換だけで `/mnt/f` や UNC の実在を仮定しない。
- manifest は `artifact:sha256:<digest>` の論理参照を持つ。ユーザー名・ドライブ文字・個人ファイルの
  絶対パスを公開 manifest に埋め込まない。ローカル設定から物理パスを解決する。
- 未接続・未設定・ハッシュ不一致は明示的なエラーにする。空の同名フォルダーを別ドライブへ自動作成しない。

### 不変の成果物と復元契約

保管庫の予定構成は `sha256/<先頭2文字>/<SHA-256>`。同じバイト列は1つだけ保存し、
既存 blob を上書きしない。一時ファイルへの書込み、サイズと SHA-256 の照合、確定の順とする。
第2コピーにも同じ検証を行い、単なるコピー成功を復元可能性の証明にしない。

Git に残す manifest は、schema version、論理参照、元のリポジトリ相対パス、サイズ、MIME、
出典・ライセンス、生成コードの commit、入力ハッシュ、環境・パラメーター、復元コマンド、
検証結果とその日付を持つ。再生成不能なものはその理由も記す。秘密・個人データのパスは載せない。
公開できない素材の詳細は公開 manifest にも追加しない。

復元ツールは一時領域に展開してサイズとハッシュを検証する。相対パスの `..`・絶対パス・
symlink による復元先の逸脱を拒否し、既存の異なるファイルを上書きしない。
欠損時は第2コピーから取得するが、同じハッシュ検査を必須とする。
復元先の内容から既存 QA を実行できた群だけ、個別の変更で現行 Git ツリーから外す。

### 移管順序と各群の gate

| 順 | 群 | Git に残すもの・移管条件 |
|---|---|---|
| 1 | johnhull の新しい再検査画像 | [D1](../../johnhull/docs/EVIDENCE_POLICY.md) に従う。検証要約・依存指紋・画像参照を Git に残す。既存台帳が参照する証跡は resolver 対応と復元検証後まで現状維持 |
| 2 | johnhull/references/processed、market_nn の派生画像・本文 | 小さい群で試す。原本・手動 gold・索引・意味レビューを保護し、引用と既存 release/QA gate が復元先で通ること |
| 3 | models の翻訳成果物 | 再生成不能に準じて扱い、版ごとの本文・画像・閲覧入口を一緒に保管。2コピーの照合と閲覧・復元を検証 |
| 4 | quant-agent-benchmark の保存済み提出物・評価 | 実行時点の提出物・採点器・設定・結果の関係を不変 manifest で固定。結果の再実行は元記録の代替にしない |

原本・手動監査・再生成不能な成果物は、独立した2コピーの照合と復元を確認するまで外さない。
退避対象の個別確認は整理計画の方針を維持する。今回の選定は一括削除・履歴書換えの許可ではない。

## Consequences

- 新規画像の重複を抑え、Git にはレビューに必要な情報を残せる。過去コミットの容量は減らない。
- F: の接続と第2コピーの更新が運用要件になる。ストレージを持たないクローンでも、小さな fixture と
  通常テストは動く設計にし、完全監査のための復元要件は明示する。
- 公開リポジトリの読者がローカル保管庫を直接取得することはできない。公開に必要な最小受入証跡は
  Git に残すか、ライセンスと公開先を個別に決める。ローカル移管だけを公開配布の代替にしない。
- 次は D1-preflight と小群の復元実証。保管量・コピー日時・復元成否を確認してから群単位で進める。
