# Sauna Architectural Basic Planning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan is executed by the parent in the existing chat; no new subagents are required.

**Goal:** 建築士へ依頼せずに進められる基本計画を、図面・断面・設備・予算・物件条件・整合する3Dまで私が作成する。

**Tech Stack:** 既存Blender 5.2.1/Cycles、Python標準ライブラリと既存導入済みライブラリ、JSON/CSV/SVG/DXF。印刷用PDFは実行時にPDFスキルで作成・描画確認する。新しい本番依存、BIMソフト導入は前提にしない。

## Global Constraints

- 東京、男性専用・1系統、物件未定。館内同時40人を計画条件とする（営業定員の確認ではない）。
- 総予算1〜2億円は総額として扱う。工事費だけの上限へ読み替えない。
- 現在の280㎡（20×14m）は仮の外形。柱、実際の壁厚、設備経路や必要避難経路を入れても収まるとは未確認。
- 空欄・未取得を0や適合へ変換しない。
- 外部への問い合わせ・相談・見積依頼・送信は行わない。
- ソースは既存の専用worktree内。生成物は共有データのarchitecture-v1/の1ルートへ集約し、v3〜v8と参考画像は上書き・削除しない。
- Fableの同じ保存済み会話を保持する。隔離ガード・権限・セッション状態を変更して再開させない。通常経路が利用できない場合は親が継続する。
- ユーザーは①〜⑤の実行を指示。実行時も、現地調査・許認可・発注・施工の承認へ拡大解釈しない。

## Review Focus

1. 床上げで深い水風呂が入っても、頭上高さや出入りが成立しなくなる場合 → Task 1で断面と実通路の両方を比較し、「成立」と断定しない。
2. 人体の静止位置が入ることを、40人・イベント20人の処理能力と取り違える場合 → Task 2で時間による集中、出入りと待機を別に確認する。
3. 製品の外寸・定格出力を、その室への適合や必要離隔と取り違える場合 → Task 3で公表値・計算・未取得の施工条件を分離する。
4. 仮条件や未見積工事をゼロ扱いし、税込総額・保証金・運転資金を二重計上又は除外する場合 → Task 5で欠落と二重計上を検出し、見積のない項目の幅と根拠を示す。
5. 他区の条例や旧通知、概念図のチェックを、その物件の法適合と取り違える場合 → Task 4で管轄・施行日・根拠・未確定事項を必須にする。

## 実行と確認の進め方

Task 0→1→2→3→4→5→6の順。ただし法令・メーカー条件はTask 0から随時拾い、後段の問題を前段へ戻す。各Taskの成果を画像・表で提示し、既に決まった嗜好の確認は繰り返さない。

Routineな寸法整理・一次資料検索・比較計算・図面作成は私が進める。ユーザーへ確認するのは、席数・深さ・総額・体験など希望を変える判断と、結果を左右する未定の運用条件。今は建築士へ依頼しないという方針を維持する。

検証は該当モジュールに限定する。計算部分は小さな独立した既知ケース・単位/欠測の検査、図面・3Dはメッシュ照合と目視。文書だけの修正にテストを追加しない。全ワークスペースのテストや広範囲のリファクタリング、コミット・公開は行わない。
