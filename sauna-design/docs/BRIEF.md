# Fable / high への制作依頼

あなたが主実装者です。ユーザーからの今回の直接指示:

> 少し良くなったけど写真のイメージと3Dのクオリティがかけ離れてる。Fable highに3dモデルを作ってもらおう。もし作り方によりいい方法があれば変えても良い。fableにゼロベースで考えてもらおう。セッションは消さないでね。

## 依頼

制作方法をゼロベースで評価し、選んだ方法で実際の3Dモデルを制作・描画してください。
助言や計画だけで止めず、動く制作ソースと編集可能なモデル、画像比較に使える実描画まで仕上げてください。
ユーザーは方式変更とFableへの実装委任を明示的に許可済みです。通常の方式・実装判断のために承認待ちしないでください。

既存ブラウザ3Dに小さな装飾を足すだけでは今回の目的を満たしません。
リアルタイム描画、オフラインのパストレーシング、素材制作・テクスチャや照明の方法を比較し、画質と再現性を優先して選びます。
最初に現行画像とモデルを調べ、なぜ品質が離れたかと選んだ方式を docs/STATUS.md に簡潔に記録し、そのまま制作してください。

## 既に確定したユーザーの希望

- 東京、サウナ東京のような体験。物件はまだなく、理想の間取りと内装を検討中。
- 男性専用の1系統、同時滞在40人。
- サ室3室: メインは定期アウフグースを開催し約20人、セルフロウリュ、高温ドライ。
- 水風呂2槽: 立って浸かる深い槽と、座って入る槽。
- 炭酸泉1槽。
- 休憩は浴室内を中心に、椅子と寝転びを混ぜる。着衣スペースは待合程度。
- 外気浴は可能なら追加。屋内だけで成立させる。
- 総事業費の希望は1〜2億円だが、この模型で予算成立を断定しない。

## 寸法と範囲

A案の外形20×14m / 280㎡は仮です。部屋の区画配置は原則維持してください。
メイン6×5m、天井2.4m仮。セルフ3.5×3.5m、高温3×3.5m、天井2.3m仮。
浴室の中央域11×4m。水風呂外形3.2×1.9mが2槽、仮水深1.2mと0.6m。炭酸泉も別に1槽。
休憩6×5.4m＋延長4.5×2.9m、天井2.7m仮。
セルフ8人、高温6人、休憩椅子18＋寝台6、ロッカー48は前版の仮置きであり、ユーザーが定員として確定した数字ではありません。
席数のために不自然な椅子・狭い通路・家具の干渉を増やさない。必要ならこれらの仮定を調整し、理由を記録してください。
構造・法規・安全性・設備容量・事業費は未検証の検討模型です。

最優先はメイン・水風呂・休憩の3空間の品質を上げることです。
全体のA配置と残りの区画もモデル上で追跡できるようにし、3空間だけを別々の無関係な室として扱わないでください。
最初にメインの1視点で方式を検証してから、同じ品質基準を水風呂と休憩へ展開してください。

## 環境

- WSL Ubuntu に Claude CLI があり、今回 fable / high の保存するセッションとして起動。
- Windows側の既存Blenderを実機で確認済み:
  /mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe
  バージョン5.2.1 LTS。
- GPU: NVIDIA GeForce RTX 5080、16 GB。WSL nvidia-smiから確認できる。
- Windows BlenderからWSLファイルを渡す場合は wslpath -w 等でWindows UNCへ変換する。
- Blender付属Pythonなど既存ツールの使用は可。必要なら公開素材を公式の配布元から取得し、ライセンスと出典を記録。
- 新しい本番依存関係の追加、OS設定の変更、アプリの大規模導入、リモートへの公開・デプロイ・送信は行わない。
- 実行するコマンド・ファイル操作は新プロジェクトと専用データルートに限定。既存の他プロジェクトは編集しない。

必須:

2. 同じ3Dから生成したメイン・水風呂・休憩の3枚。まずは小さい試写で確認し、最終は横長2000px程度以上を目安に十分なサンプル数と適切なノイズ処理で描画。
3. 参照画像とどの要素を合わせ、どの点が残ったかを記録した短い検証。

モデルはハードエッジの箱の寄せ集めにせず、適切なエッジの丸み、板の厚み、支持・継ぎ目、木目のスケール、石の細かさ、自然な間接光と影、透明な水の反射・屈折を検討してください。
必要な場所にストーブのガード、排水、換気口、照明が納まる部分を持たせます。ただし施工可能性を保証するものではありません。

画像をモデルから実際に描画し、確認してください。モデルファイルの存在だけで完成扱いにしないでください。
画像生成モデルの出力をレンダリング実績に含めないでください。

## 規模と保存

初期想定: 出力2 GB未満、GPUメモリ16 GB以内。重い処理は事前に見積もり、30 GiBを超えそうなら実行せず親に報告。
多数のretryを別々の巨大ディレクトリに残さず、同じ出力ルート内で必要な最終成果と再現情報を残す。
途中の進捗、方式の判断、完了と未検証を docs/STATUS.md に短く更新する。
現行の参考画像と旧版モデルを上書き・削除しない。
Git commit / push、他者へのメッセージ送信、公開・デプロイを行わない。

セッションはユーザーが保存を明示指定しています。会話を削除・purge・cleanupしない。
`--no-session-persistence` を使わない。新しい別セッションへ勝手に移らず、同じ会話で継続可能な状態を残してください。

最終報告には選んだ方式・実装した内容・実描画のパス・ネイティブモデルのパス・検証と残る限界を簡潔に記載してください。
